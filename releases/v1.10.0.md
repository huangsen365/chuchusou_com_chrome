# 触触搜 v1.10.0 发布说明

发布日期：2026-08-29

## 一句话总览

**长文动作按钮生成期即可见** —— 「注入X草稿 / 生成封面」不再等整篇写完才凭空出现，而是一开始就挂在工具栏上、带加载动画并说清楚当前在等什么。

## 主要更新

### ✨ 新功能

#### 按钮在文章生成过程中就出现

v1.9.0 的「注入X草稿 / 生成封面」要等 ChatGPT 整篇写完、内容稳定 800ms 后才挂上去。长文动辄写好几十秒，这段时间里工具栏上什么都没有，很容易让人以为功能没生效，于是反复刷新页面或重开对话。

现在只要识别到长文改写工作流，按钮就立刻挂到工具栏，并显示加载动画，让你知道它在等什么、等多久。

#### 等待期状态说得清楚

按钮不可用时不再是无声禁用，而是给出具体原因：

- **内容正在生成中，请耐心等待**（ChatGPT 还在写）
- **内容刚生成完成，正在确认完整性**（写完了，正在确认拿到的是整篇）
- **暂未读取到完整文章**（当前回答里没有可用的长文正文）

生成结束、内容确认完整后，按钮自动转为可点。悬停提示与无障碍标签（`aria-disabled` / `aria-busy`）同步更新，读屏用户也能听到当前状态。

#### 点击时读取最新正文

动作按钮在**点击的那一刻**重新读取当前文章内容，而不是沿用挂载时的快照。这样即使你在生成刚结束的瞬间点下去，拿到的也是完整的最终版本。

### 🛠 技术改动

- 生成中状态检测从只认 `data-is-streaming` / `.result-streaming`，扩展到通用生成信号（`aria-busy`、`data-streaming`、`data-state="generating"`、`data-status="streaming"` 等）以及页面上可见的「停止生成 / Stop generating」控件；检测时排除触触搜自己注入的元素，避免自我误判。这降低了对 ChatGPT 某一版实现细节的依赖。
- 按钮挂载与内容就绪解耦：`workflowCandidateFor` 只负责判断"该不该挂按钮"，`extractArticle` 负责"内容够不够完整"。按钮状态机新增 `generating / settling / unavailable / ready` 四态。
- `verify:long-article-actions` 与真实 Chrome 冒烟新增覆盖：按钮先于文章内容挂载、四态状态机、加载动画元素、点击时读取实时文章。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增内容脚本匹配
- 改动范围仅限 ChatGPT 页面上的长文动作按钮；X / 知乎速答、Google Docs 改写、右键菜单、Popup、侧边栏行为均不变

## 已知限制

- 沿用 v1.9.0 已知限制
- 生成中状态依赖 ChatGPT 页面暴露的通用信号；若对方同时去掉全部信号与「停止生成」按钮，按钮可能提前转为可点（此时点击仍会读取当时的实时正文，正文不完整则按不可用处理）

## 升级提示

- 从 v1.9.0 升级：在 ChatGPT 里跑长文改写时，工具栏上会**立刻**看到「注入X草稿 / 生成封面」，处于加载状态；等它自己变成可点即可，不需要刷新页面
- 其余功能与 v1.9.0 完全一致

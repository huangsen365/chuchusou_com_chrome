# 触触搜 v1.8.0 发布说明

发布日期：2026-08-26

## 一句话总览

**知乎回答/文章一键速答 ChatGPT** —— 每则回答、每篇文章的操作栏直接出现「速答」按钮，折叠的长文会先自动展开再发送，只把标题和正文交给 ChatGPT。

## 主要更新

### ✨ 新功能

#### 知乎每则内容旁直接速答

在知乎的问题页（回答列表）、专栏文章页和文章列表中，每则回答、每篇文章的操作栏都会出现一个「速答」按钮，位置在「分享」之前。点击后触触搜直接调用现有「速答 · ChatGPT」流程，打开 ChatGPT 并填入准备好的速答提示词，不需要先手动选中文字。

知乎是动态页面：滚动加载新回答、切换问题或路由后，按钮会自动补到新出现的内容上。发送中、成功、失败分别显示「发送中 / 已发送 / 重试」，避免重复点击和无反馈；知乎重建操作栏后按钮状态也会恢复。

#### 折叠正文自动展开，不会只发摘要

知乎默认把长回答收起成「阅读全文」摘要。点击速答时，触触搜会先用知乎自带的展开按钮取全文，确认展开完成后才发送。

- 展开成功 → 发送完整正文
- 展开未完成或找不到展开按钮 → 明确报错并允许重试

**折叠正文绝不会被静默当成全文发送**，避免 ChatGPT 基于半截内容作答。

#### 只发送标题 + 正文

送入速答模板的原始材料严格限定为：

```text
【知乎问题】          ← 文章则为【知乎文章标题】
……
【知乎回答正文】      ← 文章则为【知乎文章正文】
……
【正文结束】
```

不附带作者、赞同数、评论、发布时间或侧栏推荐；同一页面的其它回答也不会串进来。只有图片或没有可用正文的内容会显示为「不可用」，不会误发。

### 🛠 技术改动

- **站点内嵌速答重构为「共享运行时 + 网站适配器」两层**：动态扫描、按钮注入幂等去重、状态恢复、Toast 与投递逻辑统一收敛到 `siteFastQaRuntime`；X 与知乎适配器只处理本站 DOM。新增站点的接入成本大幅下降，接入约定见 `docs/SITE_FASTQA_ADAPTERS.md`。
- 发送端完全复用现有 `fastqa → ChatGPT → Prompt Relay → 编辑器填入` 链路，不复制第二套 ChatGPT 填入逻辑。
- legacy 生产脚本与 TypeScript/Plasmo 源码双轨同步，保证当前商店构建与后续迁移入口行为一致。
- 新增 `verify:zhihu-fastqa` 专项校验（正文隔离、输入格式、URL 规范化、manifest 加载顺序），并扩充 headless Chrome 冒烟用例，覆盖真实域名下的单实例注入、按钮位置和动态 DOM 重建。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- 无新增权限、无存储结构变化、无服务器依赖
- 原有右键菜单、Popup、侧边栏、X 推文速答和「速答 · ChatGPT」入口行为不变

## 已知限制

- 入口依赖知乎当前页面结构；如果知乎日后调整回答/文章 DOM 标记，可能需要同步更新选择器
- 本功能有意只读取标题与正文；作者、赞同数、评论区内容不会发送
- 需要登录才能查看的内容，仍以页面上实际渲染出的正文为准
- ChatGPT 的打开与自动填入仍需要可访问 `chatgpt.com`，并受用户当前登录状态影响

## 升级提示

- 从 v1.7.0 升级：重新打开或刷新知乎页面后，每则回答/文章的操作栏会出现「速答」按钮；点击即可执行「速答 · ChatGPT」
- X 推文速答（v1.7.0 功能）行为不变，只是内部改用了新的共享运行时
- 不需要迁移设置，也不会改变已有菜单布局和速答模板

## 商店描述（300 字以内，上架直接用）

触触搜新增知乎一键速答：在问题页或专栏文章中，点击回答/文章操作栏的「速答」按钮，即可把这则内容交给 ChatGPT 生成短篇、中篇和按需长篇回答。折叠的「阅读全文」会先自动展开再发送，不会只拿到摘要；只发送标题与正文，不附带作者、赞同数和评论，回答更聚焦。X 推文一键速答同样可用。继续支持多 AI 速答、触触搜百问、提示词优化与 ChatGPT Images 2.0 封面生成；全部本地处理，无新增权限和服务器依赖。

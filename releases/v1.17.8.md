# 触触搜 v1.17.8 发布说明

发布日期：2026-09-21

## 一句话总览

**ChatGPT 中途截断后重新起稿，「注入X草稿 / 生成封面」按钮能回来了** —— 同轮残稿 + 成稿的组合不再被当成「两篇文章」而拒绝。

## 主要更新

### 🐛 修复

#### 同轮残稿 + 成稿时按钮不出现

**症状**：ChatGPT 长文生成到一半被打断（网络、手动停止、模型自行重来），随后在**同一轮回复**里重新输出完整文章。v1.17.5 起同轮出现多篇文章时按钮不出现——那是为了不替用户选择投递哪一篇——结果这种「残稿 + 成稿」的常见情况也被拒绝，用户只能刷新或重新生成。

**现在**：同轮多篇时，只在满足全部条件时放行：
- 末篇是完整文章（标题、正文长度达标），且正文最后一段以完整句子结尾（句号 / 问号 / 感叹号 / 省略号，可带引号或括号）
- 前面的每一篇都明确断在正文句中（最后一段是 `<p>` 且不以句末标点结尾）；结尾是列表、标题、图片等的不据此判为残稿
- 按钮只挂在末篇成稿上，不重复注入；重新起稿生成中按钮仍禁用；投递的是成稿，不混入残稿
- 两篇都完整的文章仍不自动代选、不拼接，行为同 v1.17.5

### 🛠 技术改动

- `modules/longArticleActions.js`：`singleArticleBlock(assistant)` 统一 writing block / 含唯一 H1 的 `.markdown` 两种正文形态；`articleEnding(block)` 取 `extractArticleSnapshot().bodyHtml` 的最后一个元素，只对 `<p>` 判定 `sentence` / `fragment`；`workflowCandidateFor` 在同轮 `articleMessages.length > 1` 时要求当前为末篇、`extractArticle` 成功、结尾为 `sentence`，且此前各篇结尾均为 `fragment`。
- `scripts/lib/verify-plain-article-actions.mjs`：新增「同轮先截断、再重新起稿」场景断言（单组按钮、生成中禁用、投递不含残稿）。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增站点匹配、无新增文件
- 工作流识别标记（上一条用户提示词的 4 个标记）未变

## 已知限制

- 沿用 v1.17.7 已知限制
- 残稿判定依赖「最后一段是段落且不以句末标点结尾」；若残稿恰好断在句号处，会被当成完整文章，同轮两篇完整 → 按钮不出现（可刷新或删掉残稿）
- 成稿若以列表或标题收尾（不符合提示词的排版要求），不会被判为 `sentence`，按钮不出现

## 升级提示

- 从 v1.17.7 升级：生成中断后重新起稿的场景下按钮会正常出现；已打开的 ChatGPT 页面需刷新一次才会加载新内容脚本
- 其余功能与 v1.17.7 一致

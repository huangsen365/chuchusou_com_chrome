# 触触搜 v1.12.0 发布说明

发布日期：2026-09-01

## 一句话总览

**注入 X 草稿时自动把「他」统一成「TA」，速答按钮不再插错位置也不再乱跳** —— 少一步手动改词，按钮稳稳待在分享按钮旁边。

## 主要更新

### ✨ 新功能

#### 「注入X草稿」自动把正文里的「他」改成「TA」

从 ChatGPT 长文点「注入X草稿」时，标题和正文里出现的「他」会在写入 X 编辑器之前统一替换成「TA」，不用再进 X 编辑器逐个手动改。

替换范围有意收窄，避免副作用：

- **只作用于真正发往 X 草稿的那一份内容**。ChatGPT 页面上的原文不动，「生成封面」用的文章也不动——同一篇文章点封面还是原样。
- **只替换可见文本**。正文 HTML 里的 `href` 等属性不参与替换，注入后的超链接不会因为域名/路径里含「他」字（或转义片段）而失效。

#### 提示词新增统一的「输出语言」要求

速答与长文优化改写的提示词模板里都加入了显式的「输出语言（必须严格遵守）」段落：无论原始素材是什么语言，成品都必须用同一种目标语言完整写完，先准确理解原文再用目标语言自然表达，必要的专有名词可保留原文。

当前固定注入「简体中文」，**对中文素材的行为与上一版一致**；变化主要体现在英文、日文等外文素材上——过去产出语言偶尔会跟着原文跑，现在稳定回中文。语言值已经抽成统一的可配置入口，后续可以在设置里选择输出语言，本版尚未提供该设置界面。

### 🐛 修复

#### 知乎速答按钮不再插错操作栏

知乎部分回答/文章页面存在**嵌套的** `.ContentItem-actions`，此前固定取第一个匹配，闪电按钮可能落进外层容器，位置和「分享」按钮对不齐、看起来飘在奇怪的地方。

现在改为：优先选真正含有「分享」按钮的那一层容器；都没有则退到最内层（叶子）容器。按钮稳定停在分享按钮左边。

#### 速答按钮不再在页面动态更新时跳位

X 与知乎的插入逻辑加了幂等短路：插入前先检查按钮是否已经在正确位置（分享按钮前，或容器末尾），是就直接跳过，不再重新操作 DOM。页面加载更多内容、切换 Tab 等动态更新时，按钮不会闪一下再归位。

#### 单操作栏页面重复注入时会「认领」已有按钮

只有一个操作栏的页面上，如果原有按钮被页面结构变化挪出了容器，共享运行时现在会认领这个已存在的按钮、把它搬回正确位置，而不是再插一个新的——避免出现两个闪电图标。

### 🛠 技术改动

- 新增 `shared/promptLanguage.js`（TS 双轨 `src/shared/promptLanguage.ts`）作为提示词目标语言的单一来源，导出 `${outputLanguage}` 占位符常量、`resolve()`、`apply()`。速答 `buildFastAnswersPrompt()`、AI 任务注册表 `buildTaskPrompt()`、Google Docs 改写与对话内改写共四条 prompt 构造路径全部改走它；所有调用方当前都不传语言参数，回退到简体中文。`shared/promptLanguage.js` 已加入 manifest 内容脚本序列与 SW 的 importScripts 列表。
- 模板占位符个数校验：`articleRewritePrompts.json` 必须恰好包含一个 `${outputLanguage}`，SW（`ccsLoadArticleRewriteTemplate`）与内容脚本（`articleRewriteRuntime`）两侧加载时都校验，缺失或重复直接抛 `article-rewrite-template-language-placeholder-invalid`。改写提示词模板升到 `version: 20`。
- `modules/longArticleActions.js` 新增 `replaceArticlePayloadTa()`：用 `<template>` 解析正文 HTML 后只遍历文本节点做替换，标题与纯文本走 `replaceAllTa()`；仅在 `isX` 分支上调用，并对外导出以便测试。
- 知乎适配器新增 `findZhihuActionContainer()` 与 `isDirectShareAction()`（前者对外导出）；X 与知乎的 `insertHost()` 都加了「已在正确位置则直接返回」的短路。共享运行时改为在 root 范围内预扫描已有按钮 + `claimedButtons` 集合去重，单容器场景下认领游离按钮。TypeScript 与 legacy 生产脚本双轨同步。
- 校验脚本同步扩展：`verify:extension-smoke` 覆盖 TA 替换（含 href 不受影响）、按钮幂等插入、知乎嵌套容器选择；`verify:article-rewrite`、`verify:shared-config` 与三个 dual 校验脚本加入输出语言占位符断言。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增站点匹配
- 新增一个内容脚本文件 `shared/promptLanguage.js`（纯常量与字符串替换，无 DOM 访问、无网络请求）
- 未删除任何菜单项或入口；右键菜单、Popup、侧边栏、X/知乎速答、Google Docs 改写行为均保持

## 已知限制

- 沿用 v1.11.0 已知限制
- 「他」→「TA」是无条件的字符替换：正文里作为词素出现的「他」（如「其他」「他乡」「吉他」）同样会被替换。仅影响注入 X 草稿的那一份内容，注入后可在 X 编辑器里改回
- 输出语言当前**没有设置界面**，固定简体中文；语言约束是提示词层面的要求，实际产出仍由 ChatGPT / Claude 决定
- 知乎容器选择依赖 `.ContentItem-actions` 与「分享」文案；知乎改版调整结构或文案后可能退回最内层容器兜底

## 升级提示

- 从 v1.11.0 升级：**「注入X草稿」的产出会和 ChatGPT 页面上看到的原文不同**——所有「他」变成「TA」，这是预期行为。若某篇文章需要保留「他」，注入后在 X 编辑器里改回即可
- 「生成封面」不受影响，用的仍是原文
- 外文素材的速答与改写产出会稳定为简体中文，此前偶尔跟随原文语言
- X / 知乎速答按钮位置可能与上一版略有不同（更贴近分享按钮），属于修复后的正确位置

## 商店描述（300 字以内，上架直接用）

触触搜本版为 X 长文工作流补上最后一步手工活：一键「注入X草稿」时，标题与正文里的「他」自动统一成「TA」，链接不受影响，页面原文和封面用稿保持原样。速答按钮的位置也更稳——知乎嵌套页面不再插错容器，X 与知乎页面动态刷新时按钮不再跳位或重复出现。速答与长文改写提示词新增统一输出语言要求，外文素材同样稳定产出简体中文。继续支持 X 长文与推文速答、知乎速答、Google Docs 与 ChatGPT 一键改写、成稿直投 X 草稿与封面生成、多 AI 速答、触触搜百问与提示词优化。所有入口只准备内容并填入输入框，不会自动发送、不会自动发布；全部本地处理，无新增权限和服务器依赖。

# 触触搜 v1.16.0 发布说明

发布日期：2026-09-20

## 一句话总览

**改写稿的概念不再千篇一律** —— 概念只从素材里来、处理方式按篇轮换、最近几篇用过的不再用。三层各管一件事，配合 v1.15.0 的形式轮换，去模具化到这一版闭环。

## 主要更新

### ✨ 新功能

#### 概念只从素材里来（长文改写 + 速答）

**问题**：形式已经按篇轮换了，但概念轴此前没有任何杠杆——模型每次从同一个先验里挑，翻来覆去都是那几个「效应」「定律」。

**做法**：把方向从「从外往里挑概念」改成「从里往外长概念」：

- 改写前先在内部列一份「**素材关键词表**」：素材自己反复出现的词、说法和比喻；自带的术语、专有名词、人名 / 事件 / 产品名；描述的具体机制、现象或矛盾
- 所有要命名的概念必须能对应到表上。来源只有两条路：直接用素材自己的词（素材说「压舱石」就用「压舱石」，不翻译成「安全边际」），或用素材所属领域专门描述这个机制的术语
- 对不上表就不命名，用白话把机制讲清楚；不从外面搬通用概念贴标签
- **特异性检验**：一个概念原样搬到另外一百篇不同题材的文章里也能用，就不够特异，不用名字。互联网常见的通用心理学、经济学效应类词汇默认不用——只描述类型，**不写死任何词表**，避免机械化
- 加粗的概念必须来自关键词表或本篇第二视角；自检清单同步加 2 条
- **速答模板同步**：短篇、中篇和后续 A/B 同样适用，否则长文会从上游继承常客概念

#### 概念处理方式按篇轮换

形式轮换器（v1.15.0）新增第五个轴「概念处理」，和标题 / 开头 / 结尾 / 第二视角一起按计数轮换：

- 只用素材自己出现过的词来命名，不引入任何外部术语
- 用素材所属领域的专业术语命名，第一次出现时讲人话解释
- 机制优先：能用白话讲清楚的就不命名，只给确实需要名字的少数概念命名
- 允许至多一个概念来自本篇第二视角的类比，其余仍只从素材来

索引 `(n+⌊n/4⌋)%4`，相邻两篇必不同。**加粗上限固定「最多 6 个」，每篇一样，不轮换。**

#### 近期概念记忆

前两层压低重复概率，这一层直接排除：

- 长文改写成品**就绪时**（不需要点按钮），扩展从正文 HTML 里抽出 `<strong>` 包住的概念名称——提示词规定只有概念名称才加粗
- 本地保留最近 40 个（去重、新的在前，同一篇只记一次）
- 下一次改写时注入提示词：「最近几篇改写里已经用过的概念（本文不要再用，也不要换个说法暗示它们；素材原文本身就包含的词除外）：沉没成本、幸存者偏差、轮作」；没有记录时显示「（无）」
- 对话内「选 A」与 Google Docs 改写两条路径都生效；全部本地，不上传

### 🛠 技术改动

- 新增 `shared/rewriteConceptMemory.js` + `src/shared/rewriteConceptMemory.ts`（1:1 对等）：`extractConceptsFromHtml`（去标签 / 去首尾标点 / 大小写去重 / 30 字上限）、`mergeRecent`、`renderRecent`、`apply`、`readRecent` / `recordConcepts` / `buildRecentText`；存储键 `ccs_rewrite_recent_concepts`。已加入 `background/index.js` 与 `src/background.ts` 的 `importScripts` 列表及 manifest 内容脚本（在 `longArticleActions.js` / `articleRewriteRuntime.js` 之前）。
- `modules/longArticleActions.js` `consider()` 在成品就绪时调用 `rememberConcepts(article.bodyHtml)`，以 signature 去重，失败不影响主流程。
- `${recentConcepts}` 占位符：后台 `ccsBuildArticleRewritePrompt()`、`modules/articleRewriteRuntime.js` 回退、`src/content-modules/articleRewriteRuntime.ts` 三处填充，模板加载时校验恰好一个。
- `articleRewritePrompts.json` 双轨 `version: 24`（796 行）；`varietyPlan.conceptModes` 4 条；`shared/rewriteVariety.js` / TS 新增 `mode` 轴与「- 概念处理：…；加粗上限仍是最多 6 个。」渲染行。`fastAnswersPrompts.json` 双轨新增「概念使用要求」段（44 行）。
- 测试：`verify:article-rewrite` 新增 8 条来源规则断言、2 条「效应」示例反向断言、5 轴 n=0..200 相邻互异、概念抽取 / 合并 / 渲染 / 空兜底断言，并校验速答模板同规则；冒烟新增 4 处真 Chrome 断言（速答规则、选 A 时「（无）」、长文就绪后 storage 记录「他说」、Docs 改写提示词注入「他说」）。修掉概念轴公式在 4 的倍数处相邻相撞的边界 bug（步长改为 1）。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无服务器依赖、无新增站点匹配
- 新增一个本地存储键 `ccs_rewrite_recent_concepts`（最多 40 条 `{term, ts}`）；新增一个内容脚本文件 `shared/rewriteConceptMemory.js`（纯函数 + 本地存储，无 DOM 访问、无网络）
- 长文页按钮的工作流识别标记未变

## 已知限制

- 沿用 v1.15.0 已知限制
- 记忆只记「加粗的概念」；模型若把概念写进正文却没加粗，不会进记忆
- 记忆是本地的，换设备或清除扩展数据后重新开始；只防最近 40 个，不防模型固有偏好（这部分靠前两层）
- 「特异性检验」由模型自行判断，偶尔仍可能给常客概念找到理由；有反例请反馈

## 升级提示

- 从 v1.15.0 升级：改写稿的概念会明显跟着素材领域走，通用效应类词汇大幅减少；部分文章不再出现任何「效应 / 定律」式命名，属预期。速答的短篇 / 中篇同样受影响
- 连续改写多篇时，从第二篇起提示词末尾会多一段「最近几篇改写里已经用过的概念」
- 想清空记忆：在扩展的 service worker 控制台执行 `chrome.storage.local.remove('ccs_rewrite_recent_concepts')`
- 其余功能与 v1.15.0 一致

# 触触搜 v1.17.3 发布说明

发布日期：2026-09-21

## 一句话总览

**近期概念记忆扩到 80 条、同义词模糊去重、领域基本术语不再被误伤** —— 记忆更长、更准，同题材连写不再被逼着躲开该用的词。

## 主要更新

### 🐛 修复

#### 记忆覆盖篇数被 v1.17.2 缩短

v1.16.0 设计上限 40 条时每篇加粗 2～3 个，能覆盖 15～20 篇；v1.17.2 把加粗目标升到 4～6 个后，40 条只够 7～10 篇，写到第 11 篇第 1 篇的概念就解禁了。上限改为 **80 条**，覆盖回 13～20 篇。仍然是满了挤掉最旧的，不会无限增长；提示词里那行约四百字。

#### 换个说法就绕过记忆

去重此前是精确匹配（仅不分大小写），「锚定效应」「锚定」「anchoring」是三条，提示词里「不要换个说法暗示」抓不到这种情况。现在去重键：不分大小写、去内部空白与引号、剥掉「效应 / 定律 / 法则 / 模型 / 理论 / 原理 / 思维 / 陷阱 / 现象 / 机制」这类后缀；剥完不足 2 字保留原词（「效应」本身不会被剥空）。抽取和合并共用同一个键，变体记成一条，存的仍是原词、保留最新那个。

#### 同题材连写时领域术语被误禁

记忆是全局的、不分题材。连写十篇中国历史，「科举」「郡县制」这类本来就该用的领域词也会被记进去、下一篇被禁；原有豁免「素材原文自带的词除外」救不了模型自己该用的领域词。提示词那句改为分级：

> 最近几篇改写里已经用过的概念（本文默认不用，也不要换个说法暗示它们；只有当某个词正是素材所属领域的基本术语、不用就说不清楚时可以用，但不再加粗、不算本篇的新概念；素材原文本身就包含的词除外）

领域词能正常出现；因为不加粗，记忆也不会把它重新记一遍，不会越滚越大。这和记忆「只抓加粗」的抓取规则天然自洽，零代码。

### 🛠 技术改动

- `shared/rewriteConceptMemory.js` + `src/shared/rewriteConceptMemory.ts`：`MAX_RECENT` / `RECENT_CONCEPTS_MAX` 80；新增 `dedupeKey` / `conceptDedupeKey`，`extractConceptsFromHtml` 与 `mergeRecent` 共用。
- `prompts/articleRewritePrompts.json` 与 `src/assets-json/` 双轨 `version: 28`（802 行不变），二十二节记忆条款改为分级。
- `verify:article-rewrite`：新增上限 80、去重键等价（后缀 / 引号 / 大小写 / 「效应」不剥空）、变体抽取、变体合并保留最新、满 80 挤掉最旧五组断言。修掉潜伏的日期漂移 bug：形式安排断言正则 `[^」]+` 被开头形式文案内层「你以为」截断，且无 storage 时计数器按日期取种子，某些日期必红——正则改非贪婪，legacy 测试上下文固定 `ccs_rewrite_variety_counter = 4`。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无服务器依赖、无新增站点匹配、无新增文件
- 存储键 `ccs_rewrite_recent_concepts` 结构不变，仅上限从 40 变 80；已有记录原样沿用

## 已知限制

- 沿用 v1.17.2 已知限制
- 模糊去重只处理后缀与引号，语义同义（如「沉没成本」与「已投入成本」）仍靠提示词里「不要换个说法暗示」约束
- 「领域基本术语可以用但不加粗」由模型判断，个别情况下可能把借来的概念也当成领域词不加粗

## 升级提示

- 从 v1.17.2 升级：连续改写多篇时，提示词末尾那段近期概念会更长（最多约四百字）；同题材连写时该用的领域词会正常出现但不再加粗，属预期
- 想清空记忆：service worker 控制台执行 `chrome.storage.local.remove('ccs_rewrite_recent_concepts')`
- 其余功能与 v1.17.2 一致
- **上架说明**：本版为修复，不新增商店描述，沿用 [releases/v1.16.0.md](./v1.16.0.md) 的「商店描述」段与上架提醒。

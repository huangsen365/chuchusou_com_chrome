# 触触搜 v1.9.0 发布说明

发布日期：2026-08-29

## 一句话总览

**长文工作流打通** —— X 长文一键速答 → Google Docs / ChatGPT 一键改写 → 成稿直接注入 X 草稿或生成封面，整条链路不需要手动复制粘贴，且**每一步都不会自动发送、不会自动发布**。

## 主要更新

### ✨ 新功能

#### X 长篇文章一键速答

X Article（长文）页面会在文章自身的操作栏（分享按钮前）注入闪电入口，一键把当前长文交给现有「速答 · ChatGPT」流程。

送入速答模板的材料严格限定为：

```text
【X 长文标题】
……
【X 长文正文】
……
【正文结束】
```

排除作者、观看数、操作栏、外层推文信息和引用卡片。普通推文速答（v1.7.0 功能）行为保持不变。

#### 速答回答可分块单独复制

调整速答提示词的输出结构：短篇回答和中篇回答各自放进一个独立的 writing block，标题与 A/B 后续选项固定留在块外。这样每一篇都能用 ChatGPT 自带的复制按钮单独取走，不用再手工框选。

选择 A 时详细正文同样单独成块，结尾不带追问和引导语；选择 B 时继续沿用相同结构。

#### Google Docs 标题栏：ChatGPT 改写 / Claude 改写

在 Google 文档（`docs.google.com`）的标题栏按钮区新增两个入口。点击后触触搜会打开 ChatGPT 或 Claude，并把**当前文档链接 + 长文优化改写提示词**填入输入框。

**不会自动发送** —— 内容填好后你可以先检查、补充，再自己回车。

#### ChatGPT 回答旁：选A并优化改写

在 ChatGPT 页面，当回答符合速答的 A/B 选项结构时，复制按钮旁会出现「选A并优化改写」。点击即把「选A」与文章优化改写提示词填入输入框。

不会覆盖你已经写了一半的草稿，也不会自动发送。

#### 成稿一键「注入X草稿」

改写完成的长文，可以直接写入 X Articles 编辑器的标题和正文，省掉复制粘贴长文的麻烦。

安全约束（都是刻意设计的）：

- 只写入一个**新开的专用 X Articles 标签页**，不动你当前正在编辑的页面
- **编辑器已有内容时主动停止**并提示，绝不覆盖已有草稿
- 写入后校验 X 的自动保存确认；未读到确认会明确警告，让你自己在关页面前确认保存状态
- **永不自动发布**

#### 成稿一键「生成封面」

同一位置还有「生成封面」：用完整文章打开封面生成流程并填好极简留白提示词，同样不会自动发送。

### 🐛 修复

#### Google Docs 改写入口在账号路由变化后失效

Google 会在文档链接里动态增删 `/u/0/` 这类账号段。此前触触搜把带账号段和不带账号段的链接当成两篇不同的文档，导致来源校验不通过、改写入口点了没反应。

现在按**文档 ID** 归一化链接，同一篇文档在任何账号路由下都能正常触发；跨文档的来源校验仍然严格生效。

### 🛠 技术改动

- X 适配器新增 `twitterArticleReadView` / `twitter-article-title` / `twitterArticleRichTextView` 稳定语义选择器，长文优先识别并复用共享站点速答运行时；TypeScript 与 legacy 生产脚本双轨同步。
- 新增长文改写运行时（`articleRewriteRuntime`）与 X 草稿投递链路。**源页面从不直接跨源写入**：改为创建一个带校验和的短时本地任务，由后台把它绑定到唯一一个 X Articles 标签页，只有该标签页可以读取和完成任务，任务 24 小时过期。
- X Articles 编辑器基于 Draft.js，无法用普通 DOM 赋值写入，因此新增一个仅匹配 `x.com/compose/articles*` 的 `world: "MAIN"` 注入脚本读写编辑器状态。写入失败、超时、编辑器非空都有明确错误与 Toast，不做静默重试覆盖。
- 新增 `verify:article-rewrite`、`verify:long-article-actions` 两条专项校验并接入 `npm test`；X 专项校验与真实 Chrome 冒烟夹具扩充长文标题/正文隔离、按钮位置、跨源任务绑定与双轨一致性覆盖。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构破坏性变化、无服务器依赖
- 新增内容脚本匹配：`docs.google.com` 文档页、`chatgpt.com` 会话页，以及仅用于草稿注入的 `x.com/compose/articles*`（`world: "MAIN"`）
- 原有右键菜单、Popup、侧边栏、X 推文速答、知乎速答与「速答 · ChatGPT」入口行为不变

## 已知限制

- 入口依赖 X / 知乎 / Google Docs / ChatGPT 当前页面结构；对方调整 DOM 标记后可能需要同步更新选择器
- 「注入X草稿」依赖 X Articles 的 Draft.js 编辑器与自动保存机制；X 若改动编辑器实现需同步适配
- 改写与封面入口只准备内容并填入输入框，**发送动作始终由你自己完成**
- ChatGPT / Claude / X 的打开与自动填入受各自登录状态影响

## 升级提示

- 从 v1.8.0 升级：刷新页面后，X 长文页出现速答闪电入口；Google 文档标题栏出现「ChatGPT 改写 / Claude 改写」；ChatGPT 回答旁出现「选A并优化改写」，改写成稿旁出现「注入X草稿 / 生成封面」
- 速答的回答结构有变化：短篇、中篇各自独立成块，可以单独复制；如果你依赖旧的「三篇连在一起」格式，这版会看到明显不同
- 不需要迁移设置，也不会改变已有菜单布局

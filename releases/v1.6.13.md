# 触触搜 v1.6.13 发布说明

发布日期：2026-05-16

## 一句话总览

Popup 启动路径**全面提速** —— 消灭"点扩展图标后那段短暂白屏"的体感卡顿。**无破坏改动、无 storage schema 变化、无权限变化、对老用户升级完全静默**。

## 主要更新

### 🔧 改进

#### Popup 首次打开更快、重开秒显

**问题表现**：
- 点击扩展图标后，popup 弹出但内容区有一小段（200–500ms）白屏 / 空菜单，要等关键字 + 菜单结构都拿到才一次性渲染。
- 在 SW 冷启动场景下（Chrome 把 service worker 杀掉后第一次点扩展），等待更明显。

**根因**：
1. 老 `init()` 用 `Promise.all([loadMenuConfig(), keywordPromise])` 把**关键字获取**和**菜单结构请求**绑在一起 —— 任一条慢一点，整个 popup 都卡着不渲染。
2. Background 端 `getPopupMenuStructure()` 内的高级功能组装：百问 / 速答 / 优化 / 封面 4 个 `loadXxxConfig()` **逐个 `await` 串行**，4 倍延迟摞起来。

**修复**：
- **Popup 端解耦**：`init()` 拆 `startMenuLoad()` / `startKeywordLoad()` 两条独立异步路径。菜单先到先渲染，关键字回来再补徽章；反之亦然。
- **菜单结构缓存**：`chrome.storage.local` 按 `manifest version` 为 key 缓存上一次菜单结构。重开 popup 时**先读缓存秒显**，background 新结构回来后再静默覆盖。版本号变化自动失效，不会出现菜单陈旧。
- **700ms 兜底**：若 background 长时间未返回，先用硬编码的基础搜索 / AI 项（百度 / Google / ChatGPT / Claude / Google AI / 知乎 / 微信搜一搜 / Google 翻译）渲染。永远不会完全白屏。
- **Background 并行**：`getPopupMenuStructure()` 把 top100 / fastqa / optimize / cover 4 个 loader 同时启动，各分支用预先派发的 Promise，整体省一截首启延迟。各 loader 内部都有内存缓存，重复 await 零成本。

**效果**：
- 重开 popup（同 version）→ 缓存命中 → 几乎无感。
- 冷启动 → 700ms 内必有内容渲染（最差走 fallback，正常路径会更快）。

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- 与 v1.6.12 完全兼容；**无 storage schema 改动、无权限改动、无新依赖、无破坏 API**
- 对老用户升级**完全静默**（无权限弹窗、不被停用）
- 升级后第一次打开 popup 还没缓存，性能等同 v1.6.12；第二次起进入"秒显"

## 已知限制

- Storage 缓存的菜单结构是按 **manifest version** 作 key 的 —— 当用户在设置里**改了菜单启用/禁用项**但版本号没变，popup 仍会先显示上次缓存的菜单（约 200–500ms 后会被 fresh 结构覆盖）。对绝大多数用户无感，且 fresh 结构一定会覆盖到。
- 700ms fallback 的硬编码菜单只包含基础 8 项（百度 / Google / ChatGPT / Claude / Google AI / 知乎 / 微信搜一搜 / Google 翻译）—— 这是兜底场景，正常 background 一定能在 700ms 内返回，不会触发。
- 本版本只动了 popup 启动路径相关代码，未触碰其它 UI。侧边栏 / 右键菜单 / 内容脚本行为与 v1.6.12 一致。

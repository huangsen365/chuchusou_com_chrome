# 触触搜 v1.6.14 发布说明

发布日期：2026-05-17

## 一句话总览

Popup 启动路径**彻底重构** —— 首屏完全脱离 Service Worker，把"点扩展图标到看到菜单"的延迟从 250-700ms 砍到 < 150ms。**无破坏改动、无 storage schema 变化、无权限变化、对老用户升级完全静默**。

## 主要更新

### 🔧 改进

#### 1. Popup 首屏完全脱离 Service Worker

**问题背景**：
- v1.6.13 之前 popup 要等 `chrome.runtime.sendMessage({action:'getMenuStructure'})` 应答才能渲染
- 但 background Service Worker 冷启动要先解析 24 个 .js / 339KB 代码 —— 约 300ms
- 极端场景（SW 被强制 unload 或刚装好扩展第一次打开）首屏延迟 500-1000ms

**新方案**：
- Popup 是 extension page，**同源**可直接 `fetch(chrome.runtime.getURL('config/...json'))` 和 `prompts/*.json` —— 10-30ms 量级
- 新增 `shared/menuStructureBuilder.js` 纯函数 `CCSMenuStructureBuilder.build()` —— popup 和 background 共用，**保证菜单结构一致**
- popup 启动流程：`Promise.all(6 个 fetch)` → builder.build() → render()
- **首屏 0 次 sendMessage**，SW 冷启动对首屏可见时间**完全不影响**

#### 2. Shimmer 骨架屏 —— 极致 TTFB

- popup.html 内嵌 3 条 shimmer 骨架条（纯 CSS 动画）
- HTML 解析完（~20ms）就有视觉反馈，绝不再"白屏"
- 菜单数据到位后一次性切换为真菜单

#### 3. 彻底消除 v1.6.13 的视觉抖动

- v1.6.13 引入的 `chrome.storage.local` 菜单结构缓存 + 700ms fallback timer + fresh 覆盖逻辑全部删除
- 删除原因：本地 fetch 30-50ms 就能拿到 fresh 结构，缓存反而引入"fresh 覆盖→视觉抖动"的麻烦
- 现在只有一条路径：fetch → build → render

### 🛠 技术改动

- **新增** `shared/menuStructureBuilder.js`：纯函数式菜单构建，popup + background 共用 SSoT
- **改动** `background/base.js` `getPopupMenuStructure()`：372 行旧实现删除，改为 20 行薄包装调用 builder
- **改动** `background/index.js`：`importScripts` 列表新增 `'../shared/menuStructureBuilder.js'`
- **改动** `popup/popup.html`：删 3 个无用 `<script>` 引用（`MenuRenderer.js` / `SettingsManager.js` / `ToastHelper.js`，这三个在 popup.js 里从未被实例化）；改 `加载中...` 为 shimmer 骨架；新增 `menuStructureBuilder.js` 引用
- **改动** `popup/popup.css`：新增 `.menu-skeleton` + `.skeleton-row` + `@keyframes ccs-skeleton-shimmer`
- **改动** `popup/popup.js`：完全重写 `init()` 启动链路；删除 `POPUP_MENU_CACHE_KEY` / `POPUP_MENU_FALLBACK_DELAY_MS` / `loadMenuConfig` / `startMenuLoad` / `readCachedMenuStructure` / `writeCachedMenuStructure` / `getFallbackMenuStructure` / `initPromptLibrary` / `initDebugToggle` / `initVoiceToggle`；新增 `fetchJSON` / `ensureSettingsInit` / `loadScript` / `ensurePromptLibrary` / `_preloadEnableState`
- **改动** `popup/popup.js` `initSettings()`：合并原 5 次串行 storage.get 为 1 次（enabled / ccs_debug / ccs_voice_enabled 一次拉齐）

- **打 tag** `pre-popup-rebuild`：本次重构前的回滚锚点

## 兼容性

## 期望效果

| 指标 | v1.6.13 | v1.6.14 目标 |
|---|---|---|
| SW warm 首屏 TTFB | ~250-400ms | **< 100ms** |
| SW 冷启动首屏 TTFB | ~500-1000ms | **< 200ms** |
| 700ms fallback 视觉抖动 | 偶发 | **消除** |
| 首装第一次打开 | ~700ms | **< 250ms** |

打开 popup devtools 控制台可看到 `[触触搜][PERF] popup TTFB: XXXms` 实测埋点。

## 已知限制

- **执行菜单仍依赖 SW**：用户点了菜单后 `executeMenuAction` 还要 sendMessage 给 SW。SW 冷时这一步仍可能延迟 200-400ms 才打开标签。这是已知遗留，本次未解决（解决要把 TextLimits / keyword resolver / 字数保护一整套复刻到 popup，工作量大且重复 SSoT）。**重点**：首屏可见时间不受影响，用户感知是"菜单先出，点了后跳转"。
- **第一次点设置 / 提示词库会有 ~20ms 加载延迟**：lazy load 一次性代价，第二次零延迟。
- 本版本只动了 popup 启动路径相关代码。侧边栏 / 右键菜单 / 内容脚本行为与 v1.6.13 一致。

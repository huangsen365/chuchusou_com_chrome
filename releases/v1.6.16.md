# 触触搜 v1.6.16 发布说明

发布日期：2026-05-17

## 一句话总览

Popup / Sidepanel 首帧**零 JS 即可见可点**——把 8 个最常用菜单项直接预渲染在 HTML 里，浏览器解析完 HTML 就能交互，比 v1.6.15 的 storage 预热再快一档。**无破坏改动、无 storage schema 变化、无权限变化、对老用户升级完全静默**。

## 主要更新

### 🔧 改进

#### 1. Popup 首帧"开包即用"

**演进路径**：
- v1.6.13：5 次串行 storage.get + 700ms fallback timer
- v1.6.14：6 次同源 fetch + builder（脱离 SW，~30-50ms）
- v1.6.15：1 次 storage.get prewarm cache（~5ms）+ fetch fallback
- **v1.6.16：HTML 静态预渲染 → 首帧零等待**

**新方案**：
- `popup/popup.html` 直接写出 8 个最常用菜单项的 `<div class="menu-item" data-menu-id="..." data-url-pattern="...">...`
  - 速答 · ChatGPT / 速答 · Claude
  - 百度搜索 / Google 搜索
  - ChatGPT / Claude / Google AI 模式
  - Google 翻译
- 浏览器解析完 HTML 就立刻能看见、能点
- `popup.js` 用事件委托（`menuContainer.addEventListener('click', ...)`）统一处理这些静态项
- Dynamic 菜单（百问全套 / 速答全套 / 优化提示词 / 封面生成器 / 工具）按 v1.6.15 的 storage 预热路径异步加载完后，`innerHTML = ''` 整体替换为完整结构

#### 2. Sidepanel 同步改造

- `sidepanel/sidepanel.html` 同样写入 8 个静态核心菜单项，去掉"加载中..."占位
- `sidepanel.js` `init()` 拆为 5 段独立异步链：
  - `setupAlivePort()` 同步
  - `bindStaticMenuItems()` / `bindCopyKeywordButton()` 等绑定（同步）
  - `pinned.init()` 异步独立
  - `loadMenuConfig().then(renderMenu)` 异步独立
  - `getActiveTab() + getCurrentKeyword()` 异步独立
- 任一段失败都不再覆盖整页"加载失败"——至少静态核心菜单仍然可用

#### 3. 鲁棒性增强

- `popup.js handleClick`：用户在 keyword 还没加载完就秒点菜单时，最多等 600ms 拿到 fresh keyword 再执行（之前直接拿空 keyword 会触发"没有选中文本"提示）
- `bindStaticMenuItems` / `bindMenuDelegation` 用 `_menuDelegationBound` flag 防止重复绑定
- 动态创建的 menu item 上 `e.stopPropagation()` 防止与容器委托双触发

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- 与 v1.6.15 完全兼容；**无 storage schema 改动、无权限改动、无新依赖、无破坏 API**
- 对老用户升级**完全静默**（无权限弹窗、不被停用）
- v1.6.15 写入的 `ccs_popup_menu_prewarm` storage key 仍然兼容，作为完整菜单的快速路径
- 静态核心菜单的 8 个 URL 模板与 background SSoT 完全一致（与 `shared/menuStructureBuilder.js` / `config/unifiedMenuConfig.json` 同源）

## 期望效果

| 指标 | v1.6.15 | v1.6.16 目标 |
|---|---|---|
| Popup 首帧"看到菜单"时间 | ~30ms（storage hit）/ ~80ms（fetch fallback） | **< 10ms**（HTML 解析完即可见，零异步） |
| Popup 首帧"能点击"时间 | 同上 | **HTML 解析后 + bindEvents 后** (~15-20ms) |
| 首装首次（onInstalled 还没写完 storage） | ~150ms（走 fetch fallback） | **< 30ms**（静态菜单已在 HTML 里） |
| Sidepanel 首帧"看到菜单" | sendMessage 等 SW（~50-300ms） | **< 10ms** |
| 完整菜单加载完成（覆盖静态部分） | ~30ms | ~30ms（不变，但用户已经在交互了） |

打开 popup / sidepanel devtools console 仍可看到 `[触触搜][PERF] popup TTFB: XXXms (storage-prewarm/local-fetch)`——这是完整菜单 ready 的时间，不是首帧可见时间。

## 已知限制

- **静态核心菜单只覆盖 8 个最常用项**：百问 / 速答 / 优化 / 封面 / 工具组等仍依赖 dynamic 加载（通常 ~30ms 后到位，完整菜单会替换静态部分）。在 dynamic 加载完之前用户**只能用这 8 个核心入口**，但已能覆盖绝大多数场景
- **静态菜单与 background 的 SSoT 同步靠人工维护**：8 个核心项的 id / urlPattern 直接写死在 HTML 里，如果 `config/unifiedMenuConfig.json` / `shared/menuStructureBuilder.js` 改了 8 项中任一项的 url，需同步改 HTML。已知风险，加入开发 checklist
- **执行菜单仍依赖 SW**：用户点了菜单后 `executeMenuAction` 还要 sendMessage 给 SW。同 v1.6.14 / v1.6.15 注记，本次未解决

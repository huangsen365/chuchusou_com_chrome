# 触触搜 v1.6.26 发布说明

发布日期：2026-05-18

## 一句话总览

**修 v1.6.25 引入的 offscreen prewarm 误初始化报错**，2 行 DOM 守卫，零功能改动。

## 主要更新

### 🐛 修复

#### offscreen prewarm 触发 popup / sidepanel 误初始化

**症状**：v1.6.25 装上后，扩展安装或 Chrome 启动时控制台冒出 4 条错误：
```
[extension][popup][init-error] chrome.runtime.getManifest is not a function
[触触搜] Popup 初始化失败: TypeError: chrome.runtime.getManifest is not a function
[触触搜] Popup 初始化失败: TypeError: Cannot set properties of null (setting 'innerHTML')
[触触搜] Sidepanel 初始化失败: TypeError: Cannot set properties of null (setting 'textContent')
```

**根因**：v1.6.25 引入的 L3 offscreen prewarm 设计是这样：

```
SW onInstalled / onStartup
  → chrome.offscreen.createDocument('offscreen/prewarm.html')
    → prewarm.js 通过 <script> 顺序注入：
       popup.boot.js / sidepanel.boot.js / popup.bundle.js / sidepanel.bundle.js
```

注入的目的是让 Chrome 提前加载 + 编译这些脚本（V8 字节码 cache 预热 + AV/SmartScreen 扫描成本提前），等用户真打开 popup 时享受 warm cache。

但 `popup.bundle.js` / `sidepanel.bundle.js` 末尾各有一段自动初始化逻辑：
```js
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', bootPopupMenu, { once: true });
} else {
  bootPopupMenu();   // ← bundle 在 offscreen DCL 之后加载，所以走这条立即执行
}
```

`bootPopupMenu()` 调 `new PopupMenuRenderer().init()`，但 offscreen 文档**没有 popup 的 DOM**，且 `chrome.runtime.getManifest` 在 offscreen 上下文里 Chrome 149 行为异常，于是链式抛错：

1. `init()` 第一句 `loadVersion()` → `chrome.runtime.getManifest()` → TypeError
2. catch 块 `CCSLogger.error` + `console.error` 各打 1 条
3. catch 块调 `showError()` → `document.getElementById('menuContainer').innerHTML = ...` → null → 第二次抛
4. sidepanel 同款剧情，第 4 条错误

**修复**：给 `bootPopupMenu()` / `bootSidePanel()` 各加 1 行 DOM 存在性检查。如果当前文档里没有 popup / sidepanel 的关键容器元素（`menuContainer` / `spMenu`），直接 return，跳过初始化。

```js
function bootPopupMenu() {
  // GUARD：本 bundle 也被 offscreen prewarm 注入到预热文档里执行——
  // 预热文档没有 popup 的 DOM。检测到 menuContainer 不在就跳过 init。
  if (!document.getElementById('menuContainer')) return;
  // ... 原有 init 逻辑
}
```

sidepanel 同款。

## 已知限制 / 影响面分析

**没有功能损失**：

| 场景 | guard 结果 | 行为 |
|---|---|---|
| 真实 popup（用户点扩展图标）| `menuContainer` 在静态 HTML → guard 通过 | 完全一致，**0 差异** |
| 真实 sidepanel（用户开侧栏）| `spMenu` 在静态 HTML → guard 通过 | 完全一致，**0 差异** |
| offscreen prewarm（bug 现场）| 元素不存在 → 提前 return | 错误链断掉，不再抛 |
| plasmo dev / 直接装源码 | 模板里有这俩 ID → guard 通过 | 完全一致 |

**prewarm 预热作用保留**：bundle 仍然在 offscreen 里完整加载 + V8 编译。guard 只是阻止了"在错误的 document 上跑 UI init"这一步——而那一步本来就不是 prewarm 的目标。

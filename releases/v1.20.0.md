# 触触搜 v1.20.0 发布说明

发布日期：2026-10-18

## 一句话总览

**Claude 上也有「选A并优化改写」和长文「注入X草稿 / 生成封面」。**

## 主要更新

### ✨ 新功能

#### Claude 上的「↗ 选A并优化改写」

用「速答 → Claude」得到的回复里，Claude 会把短篇、中篇两篇回答显示成代码块，A / B 选项是两段普通文字。现在这类回复底栏的「Copy」后面会出现「↗ 选A并优化改写」，点了把与 ChatGPT、Gemini 相同的改写提示词填进 Claude 输入框：

- 输入框里已有草稿时不覆盖，不自动发送
- 回复还在生成时不出现
- Claude 较早的回复要把鼠标移上去才显示底栏，按钮也跟着它

#### Claude 上的「注入X草稿」「生成封面」

选A改写出的长文，Claude 直接显示成正文（主标题、小标题、加粗都有，没有代码块）。现在：

- 两个按钮出现在这条回复底栏的「Copy」后面，生成完成、内容稳定后才可点
- 扩展取出主标题、小标题与加粗段落再投递：X 草稿与 ChatGPT / Gemini 一致（“他”替换为“TA”，不自动发布），封面用完整文章、风格跟随侧边栏置顶、打开 ChatGPT 图片
- 只认选A改写工作流产出的长文（它前面那条用户消息是改写提示词）；普通提问的长回答不出按钮

### 🛠 技术改动

- 新增 Claude 页面适配器 `modules/claudeDom.js`（Claude 的页面结构只写在这里，`verify:site-adapters` 守卫）、`claudeSelectARewrite.js`、`claudeLongArticle.js`。
- Gemini 与 Claude 的选A按钮改为共用 `articleRewriteRuntime.js` 的 `startSiteSelectAButton(site)`，`geminiSelectARewrite.js` 只描述 Gemini 页面结构；长文按钮继续共用 `longArticleActions.js`（`articleFromRenderedRoot` 可指定主标题元素，Claude 的主标题是 h2）。
- Claude 的回复底栏由 React 管理，重渲染（例如「N minutes ago」更新）会把扩展按钮挤到最前；每次检查都会放回「Copy」后面。
- 后台：claude.ai 可以取选A改写提示词；长文来源校验 `trustedArticleSource` 认 Claude（发起页与文章来源须是同一个站点）。
- 真机复核：用扩展自己的提示词在 Claude 上实际跑了一次速答与选A改写，再在该对话上运行与仓库逐字一致（SHA-256 核对）的新代码——速答回复认出并在「Copy」后放一个选A按钮；长文认出，主标题、6 个小标题、7 个加粗概念正确提取，按钮在「Copy」后面。
- 冒烟测试（真 Chrome）新增 Claude 选A按钮与长文双动作两组场景（生成中不出 / 底栏重绘与 React 重排后恢复 / 完整填入 / 不自动发送 / 草稿保护 / 封面与 X 草稿投递 / TA 替换）。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖
- ChatGPT 与 Gemini 上的按钮行为不变

## 已知限制

- 沿用 v1.19.1 已知限制
- Claude 若把整篇长文放进 Artifact（右侧面板），正文不在对话里，按钮不会出现（实测当前直接显示成正文）

## 升级提示

- 升级后**已打开的 Claude 页面需要刷新一次**，按钮才会出现

## 商店描述（300 字以内，上架直接用）

触触搜速答、触触搜百问、提示词优化可一键发到 ChatGPT、Claude、Gemini、Grok、文心一言、Google AI，提示词自动填进输入框。现在 ChatGPT、Gemini、Claude 三家的速答回复都有「选A并优化改写」，改写出的长文可一键「注入X草稿」「生成封面」。继续支持 X 长文与推文速答、知乎速答、Google Docs 一键改写，封面生成器多种风格（墨清、韩系粉色等）与配色轮换。所有入口只准备内容并填入输入框，不会自动发送、不会自动发布；全部本地处理，无新增权限和服务器依赖。项目已以 MIT 协议开源。

# 触触搜 v1.6.25 发布说明

发布日期：2026-05-18

## 一句话总览

**针对 Chrome 部分 Beta 版本 popup 启动慢的两阶段加载架构 + offscreen 预热 + 欢迎页新增 📌 固定到工具栏教学 + 诊断工具大幅增强**。Stable 渠道用户感知"打开更稳"，开发者用户拿到更强的排查工具。

## 主要更新

### 🔧 改进

#### 1. popup / sidepanel boot + bundle 两阶段加载

之前 popup.html 串 5 个 `<script defer>`（4 个 shared/* + popup.js，共 ~80KB），renderer 主线程必须把这 5 个都 parse + execute 完才 DCL。本版改成：

```
旧：popup.html → <script defer> × 5 → DCL
新：popup.html → <script async popup.boot.js> （~10KB）→ boot 内首屏交互可用
                ↓ window.load + 2×rAF + requestIdleCallback
                → 动态注入 popup.bundle.js（~90KB，完整功能）
```

`popup.boot.js` 负责的关键交互（首屏不依赖 full bundle）：
- 静态菜单 click（leaf 直接 chrome.tabs.create）
- has-children submenu 展开 / 折叠
- 关键字 storage cache 读取
- 关键字徽章渲染
- 简单 toast

用户点扩展图标 → boot 加载执行 → **菜单立刻可点**；同时 idle 后台拉完整 bundle 备用（封面 picker / 设置面板 / 提示词库等"低频深度功能"）。

sidepanel 同款 boot + bundle 架构。

#### 2. SW offscreen 预热

`background/init` 在 `chrome.runtime.onInstalled` / `onStartup` 调用新增的 `prewarmUiDocuments()`，通过 `chrome.offscreen.createDocument({ reasons: ['DOM_PARSER'] })` 创建 `offscreen/prewarm.html`。预热页依次 load：

```
popup/popup.boot.js
sidepanel/sidepanel.boot.js
popup/popup.bundle.js
sidepanel/sidepanel.bundle.js
```

跑完发 `ccsUiPrewarmDone` 给 SW，SW 关闭 offscreen 文档。

**作用**：Chrome 的扩展脚本 loader / V8 bytecode cache / GPU 进程 Dawn 初始化 / SmartScreen 文件信誉查询等成本，**全部在用户感知不到的时机（扩展安装 / Chrome 启动后）吸收掉**。用户真点 popup 时这些都已 warm，启动延迟显著降低。

#### 3. 🩺 一键诊断报告大幅增强

新增 5 个诊断维度（原报告 8 节 → 现 12 节）：

| 新节 | 内容 |
|---|---|
| 4.4 Resource Timing | `performance.getEntriesByType('resource')` 每个加载文件的 startTime / duration / fileReadMs（responseStart - requestStart）/ size |
| 4.5 Paint Timing | first-paint / first-contentful-paint 时间戳 |
| 4.6 readyState + 事件时间线 | document.readyState 切换 + DCL + window.load 各自精确时间戳 |
| 4.7 Live fetch 测试 | 点诊断时即时 fetch manifest.json / popup.js / popup.css / icons/16x16.png，对比 4.4 原始加载耗时——能区分"Chrome script loader 路径慢"和"全局文件 I/O 慢" |
| 4.8 JS heap | `performance.memory` Chrome-only 字段：usedJSHeapSizeMB / totalJSHeapSizeMB / jsHeapSizeLimitMB |

完整 navigation timing 也从 4 字段扩到 10 字段（fetchStart / requestStart / responseStart / responseEnd / domInteractive / domContentLoaded / domComplete / loadEventEnd / transferSize / decodedBodySize）。

### ✨ 新功能

#### 欢迎页加 📌 固定到工具栏教学 section

紧贴"🎯 四种入口（任选其一）"之后新增一节：

> **📌 强烈建议：把触触搜固定到工具栏**
> 
> Chrome 默认把扩展藏在右上角的 🧩 拼图按钮里，点开扩展要多绕一步。
> 
> 1. 点击 Chrome 工具栏右上角的 🧩 **扩展（拼图按钮）**
> 2. 在弹出的列表里找到 **「触触搜」** 这一行
> 3. 点击右边的 📌 **图钉图标**，让它变蓝色（变蓝 = 已固定）
> 
> 固定后扩展图标会常驻在地址栏右侧，**点击即开 Popup / 一秒打开侧边栏**，比每次进拼图菜单快得多。

新用户装完后自动打开欢迎页（`chrome.runtime.onInstalled` 已接），这条提示会作为入门指引的一部分立刻看到。

### 🛠 技术改动

- 新增 `scripts/bundle-shared-deps.mjs`：编译期把 shared 工具 + popup/sidepanel 主代码拼成 bundle，patch HTML 改成 `<script src="popup.boot.js" async>` 单引用。
- 新增 `popup/popup.boot.js`（手写，~375 行）：首屏交互 bootstrap
- 新增 `popup/popup.bundle.js`（build 生成，~90KB）：完整 popup 逻辑
- 新增 `sidepanel/sidepanel.boot.js`（手写，~338 行）+ `sidepanel/sidepanel.bundle.js`（build 生成）
- 新增 `offscreen/prewarm.html` + `offscreen/prewarm.js`：offscreen 预热文档
- 新增 `src/background/initPrewarming.ts` 的 `prewarmUiDocuments()`，`InitOrchestrator.runFullPrewarming` 中调用
- `package.json` plasmo:build chain 增加 `bundle-shared-deps.mjs` 两次（pre-plasmo 处理源码、post-plasmo 处理 build 产物）
- `eslint.config.mjs` browser globals 加 `PerformanceObserver` + `screen`（诊断 IIFE 用）
- 跳过版本号 v1.6.24（保留给将来可能的紧急 hotfix；本次直接到 1.6.25）

## 兼容性

- Chrome 114+（不变）
- Manifest V3
- 用户已有数据全部兼容

## 已知限制

- 首次点 popup 时如果 offscreen 预热还没完成，boot 依然可能等 renderer init（视 Chrome 版本和 GPU 后端）。预热是异步的最佳努力（best-effort），不是 100% 命中。
- `prewarmUiDocuments` 仅在支持 `chrome.offscreen` API 的 Chrome 110+ 上生效（minimum_chrome_version 114 已要求）。

## 升级提示

从 v1.6.23 升级：商店推送后浏览器自动更新即可。

主观感受变化：
1. **新用户欢迎页有 📌 固定到工具栏教学** —— 一眼看到怎么把图标钉到地址栏
2. **popup / sidepanel 首屏可能更稳** —— 首屏只跑极小的 boot，完整功能 idle 后才加载
3. **🩺 诊断按钮报告更详细** —— 排查问题给开发者的信息量翻倍

完整商店描述沿用 v1.6.20 大版本即可（纯 patch 性能 + UX 改进，无新主功能 + 无 UI 重构）。

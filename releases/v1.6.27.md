# 触触搜 v1.6.27 发布说明

发布日期：2026-05-21

## 一句话总览

**长 prompt 自动中转机制从 ChatGPT 扩展到 5 个 AI 引擎**（chatgpt.com / claude.ai / grok.com / 文心 / Google AI 模式 udm=50），超长选区在所有 AI 入口都不再被 URL 截断。

## 主要更新

### 🐛 修复

#### 超长选区在 Claude / Grok / 文心 / Google AI 模式上被 URL 截断

**症状**：当用户选中很长的文字（典型场景：3000+ 字一段文章 + 优化提示词模板拼接后超过 5500 字符），通过右键 / popup / sidepanel 跳转到下面任一引擎时，目标站收到的 prompt 会被浏览器或目标站截断到地址栏可承受长度（通常 2048~6000 之间，各浏览器/各站点不一）：

- claude.ai
- grok.com
- yiyan.baidu.com
- google.com/search?udm=50（Google AI 模式）

只有 chatgpt.com 在 v1.6.26 之前就已经走了 relay 中转所以没事。

**根因**：v1.6.20 引入的"长 prompt → 改用 storage 短标识跳转 → content script 拿到 ccs_pp=<id> 后 sendMessage 回 SW 取完整 prompt → 自动填到 composer"机制（`background/chatgptPromptRelay.js`），最初设计时只识别 `chatgpt.com` 域名（`host === 'chatgpt.com' || host.endsWith('.chatgpt.com')`），其它 AI 站没有走 relay 路径，直接拼到 URL query 跳转，于是命中浏览器/目标站长度上限被截。

**修复**：把引擎检测泛化到统一 `ccsGetAIEngineForUrl(url)`：

```js
// 之前
function ccsIsChatGptUrl(url) {
  const host = new URL(url).hostname.toLowerCase();
  return host === 'chatgpt.com' || host.endsWith('.chatgpt.com');
}

// 现在
function ccsGetAIEngineForUrl(url) {
  const parsed = new URL(url);
  const host = parsed.hostname.toLowerCase();
  if (host === 'chatgpt.com' || host.endsWith('.chatgpt.com')) return 'chatgpt';
  if (host === 'claude.ai' || host.endsWith('.claude.ai')) return 'claude';
  if (host === 'grok.com' || host.endsWith('.grok.com')) return 'grok';
  if (host === 'yiyan.baidu.com') return 'yiyan';
  if ((host === 'google.com' || host.endsWith('.google.com'))
      && parsed.searchParams.get('udm') === '50') return 'google-ai';
  return '';
}
```

任一引擎返回非空 + URL 长度 > 5500 字符 → 改 relay-only URL `https://<host>/?ccs_pp=<id>`，完整 prompt 暂存 `chrome.storage.local` 30 分钟 TTL；content script 在目标页 init 时检测 ccs_pp 参数 → sendMessage 回 SW 取完整 prompt → 自动填到 composer + 提示"已自动补充完整提示词，请确认后发送"。

### 🔧 改进

- **AI 引擎检测唯一权威源**：替换 4 处 (`background/chatgptPromptRelay.js`、`background/events.js`、`background/menuHandlers.js`、`src/background/menuHandlersAttach.ts`、`content.js`) 散落的 host 硬判，集中到 `ccsGetAIEngineForUrl()`，将来加新 AI 引擎只需改一处。
- **URL 模板新增 `${KEYWORD}` 占位符**（之前只识别 `${PROMPT}`）：让"普通 AI 对话"快速通道（如 `https://claude.ai/new?q=${KEYWORD}`）能复用同一份 relay。

## 兼容性

- Chrome 114+（不变）
- Manifest V3
- 用户已有数据全部兼容
- **API 完全后向兼容**：旧 `ccsPrepareChatGptPromptUrl` / `ccsAckPendingChatGptPrompt` 等 6 个老 globalThis 函数全部保留为 alias 指向新实现；老 `ccsFillChatGptPrompt` action 与新 `ccsFillAIPrompt` 并存于 message listener；老 storage key `ccs_chatgpt_pending_*` 不存在的话也不会被读到（v1.6.26 之前未消费完的 relay 会自然过期）。

## 已知限制 / 影响面分析

| 入口 | 改动 | 行为差异 |
|---|---|---|
| 右键菜单 → 5 个 AI 引擎 | `menuHandlers.js` 4 个 case 接 `openMenuUrlWithAIRelay` + 新增 `ccs-grok` case | 短 prompt → 完全一致直跳；长 prompt → 改走 relay |
| popup/sidepanel → 5 个 AI 引擎 | `events.js:executeMenuAction` 接 `ccsOpenMenuUrlWithAIRelay` + 4 个 legacy switch-case 同款 | 同上 |
| SSoT 快速通道 `tryOpenMenuUrl` | 命中 AI URL 自动转 relay，否则原路 chrome.tabs.create | 同上 |
| 速答 / 百问 / 优化 (`runAITaskByMenuId`) | 已经走 relay (v1.6.20 起)，本版只换了 API 名字 | 无差异 |
| ChatGPT（已经走 relay 的入口） | API 改名 + alias 保留 | 行为完全一致 |

**新增 prompt 不会被相同关键字反复中转**：relay 只在 `directUrl.length > 5500` 时触发，短 prompt 走老路直接拼 URL 跳转，零 storage 落库。

## 升级提示

- 选超长文（5500+ 字符 prompt 等价）走 Claude / Grok / 文心 / Google AI 模式时，**之前**会到目标站发现内容被截，**现在**会自动补全。
- 短选区行为完全没变。
- popup / sidepanel / 右键菜单三个入口都走同一份 relay，行为统一。

完整商店描述沿用 v1.6.20 大版本（patch 修长 prompt 截断 + 引擎扩展，无新 UI 无破坏改动）。

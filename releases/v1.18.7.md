# 触触搜 v1.18.7 发布说明

发布日期：2026-09-26

## 一句话总览

**「选A改写」的长文固定放进 writing block** —— 保留 v1.18.6 的主标题与小节结构，块标题直接用文章主标题。

## 主要更新

### 🐛 修复

#### 「选A改写」有时不进 writing block

v1.18.6 修好了「选A改写」长文没有标题、没有分节的问题，但当时的覆盖写法太宽：

- 速答提示词的 A 规则例外写成「篇幅、结构和排版全部以改写提示词为准」，把 A 规则里「放进一个独立的 writing block」也一起取消了
- 改写提示词第二十八节把「放进一个 writing block」列进了要撤销的旧要求，又写了「无论是否使用 writing block」

结果用不用 writing block 由模型自行决定：同一模型（gpt-5-6-thinking）、同一版提示词的 7 个对话里，只有 2 个进了 writing block，其中 3 个是同一分钟内生成的。

现在：
- 改写提示词**无条件要求**整篇文章（从主标题到最后一段）放进**同一个** writing block，不拆成多个，块外不写说明
- writing block 的**标题直接用文章主标题**，不再出现取自选项文字的「详细内容」；块内照旧以主标题开头、分成 3～6 个小节
- 覆盖句只撤销「只放正文、不得出现标题」「约 100 句」，不再动 writing block
- 速答 A 规则的例外只放开标题、分节与篇幅，全文仍放进一个独立的 writing block
- 改写目标平台没有 writing block 功能时（例如 Google Docs 改写选择 Claude），直接输出正文，不改用代码块
- 最终自检加入「是否整篇放进同一个 writing block、块标题是否为主标题」

### 🛠 技术改动

- 长文改写提示词版本 31 → 32。
- `verify:article-rewrite` 断言 writing block 要求与平台兜底句存在，且覆盖句不再包含「放进一个 writing block」或「无论是否使用 writing block」（用 v1.18.6 的写法验证会报错）。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖
- 只改提示词文本，扩展代码无变化

## 已知限制

- 沿用 v1.18.6 已知限制
- writing block 是否生效取决于 ChatGPT 端功能；提示词只能要求，最终由模型执行

## 升级提示

- 从 v1.18.6 升级后，**已打开的 ChatGPT 页面需要刷新一次**才会用上新提示词
- 已有的速答对话里，再点一次「选A改写」即可得到放在 writing block 里、带主标题和小节的长文

# 触触搜 v1.6.17 发布说明

发布日期：2026-05-17

## 一句话总览

**纯技术建设版本**——Plasmo 迁移 Phase 2 + Phase 3 部分落地：9 个共享/纯工具模块 port 到 TypeScript（约 2700 行 TS），每个都配 dual-run 验证脚本守护 SSoT 不漂移。新增冷启动性能诊断工具 + Chrome Canary 自动化测试启动器。**生产代码（manifest / background / popup / sidepanel / content / shared 老路径）一行未改**，用户感知行为与 v1.6.16 完全一致。

## 主要更新

### 🛠 技术改动

#### 1. Plasmo 迁移 Phase 2 + Phase 3：9 个模块 TypeScript 化

下列模块全部 port 到 TS，**与 legacy 文件并存、不替换生产路径**。legacy `globalThis.*` 全局加载链不变，老 importScripts 继续主导生产运行时；TS 版本供未来真正切到 Plasmo entrypoint 时使用。

| 类别 | Legacy 路径 | TS 路径 | 说明 |
|---|---|---|---|
| 共享 builder | `shared/menuStructureBuilder.js` | `src/shared/menuStructureBuilder.ts` | popup 菜单结构构建器（被 popup + background 共用） |
| 共享 keyword 客户端 | `shared/keywordClient.js` | `src/shared/keywordClient.ts` | popup/sidepanel 拿 keyword 的统一封装 |
| 数据常量 | `background/utils/Constants.js` | `src/background/utils/Constants.ts` | 15 张纯数据表（MENU_DEFINITIONS / FAST_QA_QUICK_ITEMS / OPTIMIZE_CATEGORY_TITLES 等）。chrome.* 副作用 / 可变状态留 legacy |
| 文本工具 | `background/utils/TextUtils.js` | `src/background/utils/TextUtils.ts` | 11 个纯函数（formatMenuTitle / cleanupTitleKeyword / extractKeywordFromTitle 等）参数化注入依赖 |
| 长度保护 | `background/utils/TextLimits.js` | `src/background/utils/TextLimits.ts` | 保留 `TEXT_LIMITS_ENABLED = false` 总闸，toast 副作用留 legacy |
| Logger | `background/Logger.js` | `src/background/Logger.ts` | class + getLogger + logMenuEvent，移除 import 时的 globalThis._loggerDebug 副作用注册（改为显式 registerLoggerDebug 函数） |
| 菜单 ID 常量 | `background/menuIds.js` | `src/background/menuIds.ts` | 完整 port，保留 legacy `MENU_IDS.TONGYI` 未定义 bug 以确保 dual-run 一致 |
| URL 构建器 | `background/URLBuilder.js` | `src/background/URLBuilder.ts` | 完整 port URLBuilder class，`openMultipleUrls`（chrome.tabs.create）留 legacy |
| 菜单注册表 | `background/MenuRegistry.js` | `src/background/MenuRegistry.ts` | 数据 + renderTitle / 决策逻辑全部 port，syncGroup/syncAll 改为通过 `updater` 参数注入解耦 chrome.contextMenus.update |
| AI 任务注册 | `background/tasks/AITaskRegistry.js` | `src/background/tasks/AITaskRegistry.ts` | TASK_DEFINITIONS / normalizeTask / resolveMenuId / buildPromptFromTask 等纯函数；loader 通过 fetcher 参数注入 |

#### 2. dual-run SSoT 守护脚本（接入 `npm test`）

每个 legacy 模块都配了对照 TS 跑相同输入的"双跑"验证脚本，**任何一边的实现漂移都会让 CI 立即失败**：

- `scripts/verify-menu-structure-builder-dual.mjs` —— 7 场景 + 4 张常量表
- `scripts/verify-background-utils-dual.mjs` —— Constants 15 表 + TextUtils 7 函数 × 多 case + TextLimits 边界（含 enabled / disabled 路径）+ Logger 结构
- `scripts/verify-background-pure-modules-dual.mjs` —— menuIds（3 表 + 10 函数）+ URLBuilder（static + instance + loadFromConfig）+ MenuRegistry（register / renderTitle / getStats）+ AITaskRegistry（resolveMenuId 17 case + buildPromptFromTask 用真实 prompts json）

技术细节：legacy JS 走 `node:vm` 共享 globalThis 模拟 SW importScripts 加载（chrome.* stub）；TS 走 `typescript.transpileModule` + 自建递归 CJS resolver。

`npm test` 现跑 **7 道关**：lint / typecheck / verify:shared-config / verify:menu-structure-builder / verify:menu-structure-builder-dual / verify:background-utils-dual / verify:background-pure-modules-dual。

#### 3. 冷启动性能诊断工具

- **`scripts/perf-cold-popup.mjs`**（`npm run perf:cold-popup`）：纯 Node 静态扫描器，不开 Chrome 就能给出 popup 启动链 inventory —— 同步加载文件数、字节量、`chrome.storage.local.get` / `chrome.runtime.sendMessage` / `fetch` 调用次数、lazy-load 模块清单、cold-disk read 时间模拟、与 Plasmo demo 的对比表。
- **`scripts/test-perf.sh`**（`npm run perf:test`）：一键启动**干净的 Chrome Canary** 临时 profile + 自动加载本地 build + 把性能测量命令塞进剪贴板。专门用来诊断"线上慢 / 本地快"的 dev-vs-prod 差异。
  - 自动检测 Chrome 变体：Canary > Beta > Dev > Chromium > Stable（因 Google Chrome 137+ 屏蔽 `--load-extension`，必须用其他变体）
  - 自动处理非 ASCII 项目路径（OneDrive-个人 等）：镜像到 `/tmp/ccs-ext-mirror`
  - 自动预设 Developer Mode：profile 启动时 chrome://extensions/ 已开 toggle
- **实测基线**（v1.6.16 + Canary truly-cold SW）：
  - Popup 首帧渲染：**34 ms**（接近 Plasmo demo 物理极限）
  - Sidepanel 首帧 paint：**104 ms**
  - 结论：v1.6.13-16 的 4 版性能优化已生效，popup / sidepanel 当前均不是瓶颈

#### 4. Plasmo build pipeline 守护

`scripts/verify-plasmo-package.mjs` —— 校验 `plasmo package` zip 包含 manifest 引用的必需入口 + 不含 `src/` / `docs/` / `.plasmo/` / `node_modules/` 等源码目录。`npm run plasmo:package` 自动跑。

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- **与 v1.6.16 完全兼容**：无 storage schema 改动、无权限改动、无新依赖、无破坏 API
- **对老用户升级完全静默**（无权限弹窗、不被停用）
- ZIP 内容与 v1.6.16 几乎一致——TypeScript 源码、verifier 脚本、迁移文档等内部建设文件**不进商店 zip**（被 build.sh 白名单排除）

## 已知限制

- **Plasmo 重构远未完成**：当前完成度约 **6%**（约 1300 + 1400 = 2700 行 TS / 21000+ 行 legacy）
  - ✅ Phase 0/1/2 完整 + Phase 3 纯模块部分
  - ❌ Phase 3 剩余 background（base / config / events / menuBuilder / menuHandlers / KeywordService / KeywordSyncManager / StateManager / menuSystem）
  - ❌ Phase 4 popup React 化
  - ❌ Phase 5 sidepanel React 化
  - ❌ Phase 6 content script + 悬浮面板 + dockbar
  - ❌ Phase 7 static pages（welcome / members / privacy / offscreen / voice-permission）
  - ❌ Phase 8 build pipeline 替换（`./build.sh` 仍然主导发版）
- **TS 版本目前没有真实生产消费者**：所有 production 路径仍走 legacy `globalThis.*` importScripts，TS 模块仅为后续切换 Plasmo entrypoint 备好
- **不要凭"本轮已 port" 删除 legacy 同名文件**：删之前必须先有真实消费者切到 TS 版本，并 Chrome 浏览器手动验收过

## 升级提示

- 老用户**无需任何操作**，自动更新静默升级，体验与 v1.6.16 一致
- 本地开发者：`git pull` 后跑一次 `npm install`（无新依赖也无害），后续 `npm test` 会自动跑新增的 dual-run 校验
- 想看 popup 启动是不是真的快了：`npm run perf:cold-popup` 立刻给结论；想看真实 Chrome 测量：`npm run perf:test`（需要装 Chrome Canary）

## 回滚预案

如新版本异常：

```bash
git revert <commit-hash>
# 或回到上个稳定版
git reset --hard v1.6.16
```

本次改动**完全不动生产代码**，回滚等同于"删除一些 TS 文件和 verifier 脚本"。

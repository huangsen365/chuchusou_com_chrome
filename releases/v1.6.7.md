# 触触搜 v1.6.7 发布说明

发布日期：2026-05-13

## 一句话总览

三端封面生成器 pin 状态一致化 —— 右键菜单顶层、popup 顶部都加了与 sidepanel 同源的置顶快捷启动；popup 顺手修了展开 submenu 被 footer 盖住、橙色按钮窄屏换行两个小问题。**无破坏改动、无 storage schema 变化、无新依赖。**

## 主要更新

### ✨ 新功能

#### 右键菜单顶层新增置顶封面生成器项

之前用户要在右键菜单用封面生成器，必须右键 → 高级功能 → 封面生成器 → 选风格（3 层深）。v1.6.7 起，顶部直接有：

```
触触搜
├── 🔍 触触搜（标签）
├── 🎨 封面生成器 · 二次元可爱       ← 新增，与 sidepanel/popup pin 同源
├── ───────
├── 速答 - ChatGPT
├── 速答 - Claude
├── ...
└── 高级功能
    └── 🎨 封面生成器（5 风格 submenu，原入口保留）
```

**核心：与 popup / sidepanel pin 同源 `chrome.storage.local`。** 用户在 sidepanel 切换了风格（比如改成「小红书封面」），右键菜单标题通过 `chrome.storage.onChanged` 监听**实时变化**——不用重启浏览器、不用 reload 扩展。

技术细节：
- 标题构造：`🎨 封面生成器 · <category.label>`（自定义则显示 `🖌️ <预设文本截断 15 字>`）
- 自定义但未填文本 → 退回默认 `anime-cute`，与 sidepanel / popup 同逻辑
- 状态同步用 `chrome.contextMenus.update()` 而非 rebuild —— 菜单可能正在用户使用中，update 单项体验远比重建整棵菜单好；菜单未创建时 `lastError` 静默吃掉，依赖下次 `createContextMenus()` 拿最新 storage
- `menuHandlers` 层做 menuId 翻译：`ccs-cover-pinned` → `ccs-cover-{cat}-chatgpt-images`，复用既有 `runAITaskByMenuId` 快速通道，字数保护 / ratio 注入 / 日志全部复用
- 顶层 pin 与 advanced submenu **并存**：重度用户一键启动，需切换风格仍可走 submenu

#### Popup 顶部新增置顶封面生成器卡片

Popup 也有了与 sidepanel `.sp-pin` 同款的暖色琥珀渐变卡片，padding 紧凑适配窄屏。

```
┌────────────────────────────────────────┐
│ 🔍 触触搜    [keyword]    📋          │  ← header
├────────────────────────────────────────┤
│                            5:2         │  ← 右上角小字（当前比例）
│ [🎨]  封面生成器  🌸 二次元可爱       │  ← 新增卡片，点击整张触发
├────────────────────────────────────────┤
│ 速答 · ChatGPT                        │
│ ...菜单 ...                            │
└────────────────────────────────────────┘
```

不带编辑按钮（popup 仅快捷启动，要换风格 / 比例去 sidepanel ✏️），保持 popup 简洁。点击整张卡片一键启动当前置顶风格 + 关键字，行为与 sidepanel 完全一致（同样的 `executeMenuAction(menuType:'cover')` 调用）。

#### 自定义风格新增第二个「💡 不知道填什么？」按钮

之前 sidepanel 自定义风格 textarea 旁只有一个「💡 不知道填什么？」按钮（跳 ChatGPT 让它列 30 个风格）。现在追加 (2)：

| 按钮 | 跳转 | 灵感来源 |
|---|---|---|
| 💡 不知道填什么？(1) | `chatgpt.com/?prompt=...` | ChatGPT 定制化输出 30 个风格名 |
| 💡 不知道填什么？(2) | `google.com/search?q=ChatGPT%20Images%202.0%20提示词` | Google 搜索：社区博客 / Reddit / 小红书帖 等通用结果 |

两种渠道互补，定制 + 通用都覆盖。两按钮共享 `.sp-pin-custom-help` 样式，容器 `flex-wrap: wrap` 自动处理窄屏换行。

### 🔧 改进

#### Popup 展开 submenu 后自动滚动到可视区

之前用户在 popup 滚到底部展开「高级功能」等 submenu 时，展开内容最后一行常被 fixed `.menu-footer`（56px）盖住，必须手动再滚才能看到。

修复路径有两版：

| 版本 | 实现 | 结果 |
|---|---|---|
| 第一版 | `submenu.scrollIntoView({block:'nearest'})` + CSS `scroll-padding-bottom: 64px` | 在部分 Chrome 版本上对 `block:'nearest'` 不可靠，最后一行仍被 footer 盖住 |
| 第二版（采用） | `transitionend` 后用 `getBoundingClientRect()` 量 submenu 底边，跟 `window.innerHeight - 68` 比较，超出就 `scroller.scrollBy({behavior:'smooth'})` | 强制把 submenu 底部抬到 footer 上方 12px |

仅在「展开」动作触发（`!collapsed → collapsed` 不滚），收起不会带来意外滚动。

#### 「打开/关闭侧边栏」橙色按钮加 nowrap

popup 底部 `.panel-toggle` 之前没设 `white-space`，小屏幕下「📑 打开侧边栏」/「📕 关闭侧边栏」会被折成两行。加 `white-space: nowrap` 一行解决。

### 🛠 技术改动

- 三端 pin 状态走同一套 `chrome.storage.local` key：`PIN_STORAGE_KEY` / `CUSTOM_LINE_KEY` / `RATIO_KEY` / `CUSTOM_PURPOSE_KEY`。任何一端改 → 通过 `chrome.storage.onChanged` 实时同步给其它两端，**无需手动刷新**。
- 右键菜单 SW boot 顶层调 `installCoverPinSync()` 注册一次 storage listener；监听 3 个 watched key 变化时 `chrome.contextMenus.update()` 单项标题。
- `popup/popup.js` 新增 `initPinnedCover()` / `loadPinStorage()` / `loadCoverConfig()` / `renderPinnedCover()` / `bindPinnedCover()` / `executePinnedCover()`，参数 / 行为完全照搬 sidepanel `PinnedAction.execute()`。
- 改动文件：`background/menuBuilder.js` / `background/menuHandlers.js` / `popup/popup.html` / `popup/popup.css` / `popup/popup.js` / `sidepanel/sidepanel.html` / `sidepanel/sidepanel.js`。

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- 与 v1.6.6 完全兼容；无 storage schema 改动、无新依赖
- 老用户升级后看到的差异：
  - 右键菜单顶部多一个 `🎨 封面生成器 · <你之前选的风格>` 项
  - Popup 顶部多一张暖色琥珀渐变的置顶卡片
  - Popup 展开长子菜单滚动到底部时最后一行不再被 footer 盖住
  - Popup 底部「打开/关闭侧边栏」橙色按钮窄屏不会换行
  - Sidepanel 自定义风格 textarea 旁多一个 `💡 不知道填什么？(2)` 按钮

无。

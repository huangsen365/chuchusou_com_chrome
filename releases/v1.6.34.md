# 触触搜 v1.6.34 发布说明

发布日期：2026-06-13

## 一句话总览

**右键菜单"第一次就显示关键字"系列根治** —— 选中即显（Chrome 原生 `%s` 零延迟代入）、输入框选区不再折叠、新开页面的页面关键词不再被竞态抹掉。

## 主要更新

### 🐛 修复

#### 1. 选中文字后第一次右键看不到关键字（第二次才有）

**机理**（毫秒级时间线 + 真菜单截图取证）：原生右键菜单**弹出后不重绘**；"选区→菜单标题"的异步更新链路在后台冷启动时实测 +417ms 才到达，而菜单 +251ms 就绘制了——物理上不可能靠"更快地更新"解决，且 macOS 的菜单在 mousedown 瞬间就弹出。

**根治**：选中状态下，菜单切换为 selection 专属树，顶层标题 `🔍 搜："%s"`——`%s` 由 **Chrome 在绘制瞬间原生代入**当前选中文本，完全不经过扩展管道。第一次右键、刚选完立刻右键、后台冷启动，全部免疫。子菜单（百度/Google/各 AI/速答/百问/优化/工具）完整保留，各搜索项标题同样实时显示选中文字。

#### 2. 输入框内选中文字时，菜单只显示一长串扩展名

Chrome 规则：扩展有两个以上"当前上下文匹配"的顶层菜单项时，全部折叠进以扩展名命名的父项。输入框内选区会同时命中 `selection` 与 `editable` 两个上下文，触发折叠。修复后上下文绝对互斥，输入框内选区同样第一次直显选中文字。

**取舍**：**空**输入框右键不再显示本扩展菜单（与绝大多数扩展行为一致）。

#### 3. 新开页面（无选区）菜单不显示页面关键词，切换标签页后才出现

新开标签会触发多个异步事件并发刷新菜单标题，其中拿到空结果的写入者若最后落地，标题就被抹成光板（时间线实测：+46ms 写对 → +54ms 被抹掉）。已在状态唯一汇聚点加**单调性守卫**：同一标签页、URL 未变时，空关键字不得覆盖新鲜的非空标题。三连确定性验证通过（每轮均有一次清空企图被拦截）。

#### 4. 页面加载中右键标题滞后

页面标题一到达即刷新菜单标题，不再等待页面完全加载（静态资源慢的页面以前要等好几秒）。

### 🛠 技术改动

- 视觉取证体系：有头 Chrome 真弹原生菜单 + `screencapture` 截图判读（原生菜单内容无任何 API 可读）；`Debugger.pause` 等价模拟 SW 冷启动的毫秒级时间线复现脚本
- 冒烟回归扩充：选区孪生树注册探针、新开标签标题竞态回归、标题先行刷新断言；标题守卫 4 场景单测
- `docs/TESTING_PLAYBOOK.md`：测试与排障方法论手册

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **改动范围**：`src/background/menuBuilderAttach.ts`（孪生树）/ `menuHandlersAttach.ts`（点击归一化）/ `menuStateOrchestrator.ts`（守卫）/ `background/events.js`（标题先行刷新 + title 回填）。不动 storage schema、消息协议。

## 已知限制

- **Grok 偶发换行闪烁**：沿用前版已知限制。
- 防复制类站点（右键瞬间清空选区）在后台冷启动的极小窗口内，菜单可能显示页面关键词而非选中文字（选中内容仍会正确用于点击动作）。

## 升级提示

- 从 v1.6.33 升级：商店推送后自动更新即可
- 主观感受：① 选中文字**第一次**右键，顶层即显 `🔍 搜："你选中的文字"`；② 输入框里选中文字右键同样直显；③ 新开任意页面不选字右键，`🔍 触触搜: "页面标题"` 稳定出现，不再需要切标签页

完整商店描述沿用 v1.6.20 大版本（本版为 patch）。

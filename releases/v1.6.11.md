# 触触搜 v1.6.11 发布说明

发布日期：2026-05-16

## 一句话总览

解决两个长期存在的老问题：**侧边栏在 chrome:// 内置页拿不到关键字**（根治）+ **关键字徽章切换时的跳跃感**（彻底锁死布局）。同时把 popup / sidepanel / 右键菜单 三个入口的关键字获取链路统一过 `KeywordService` 门面（意图驱动）。**无破坏改动、无 storage schema 变化、对老用户升级无权限弹窗**。

## 主要更新

### 🐛 修复

#### 1. 侧边栏在 chrome:// 内置页拿不到关键字（根治）

**问题表现**：
- 直接进入 `chrome://settings/help` 等内置页，popup 能正常显示关键字（页面 title），但**侧边栏徽章是空的**
- 必须切到 `https://google.com` 之类的 HTTPS 页面再切回来，侧边栏才能拿到
- 在 `chrome://newtab` / `about:blank` / 扩展页面 等也有类似问题

**根因（双重）**：

1. **权限不够**：manifest 之前只声明 `activeTab` 权限，对**长期挂着的侧边栏**不够。`activeTab` 只覆盖"用户主动激活那一瞬间"，侧边栏被 `chrome.tabs.onUpdated` 事件驱动的查询往往落在 `activeTab` 授权窗口外。结果 Chrome **把返回 tab 对象里的 `url` 和 `title` 字段抹掉**（不是字段为空那么简单，是被剥离）。
2. **前端早期空快照**：即使权限补齐，侧边栏在事件早期被叫醒时 `chrome.tabs.query` 也可能拿到 tab.title=''。前端拿什么传到 background，background 就用什么，没办法自救。

**修复**：

1. **`manifest.json` 新增 `tabs` 权限**：解锁 `chrome.tabs.get(tabId)` 拿完整字段。**对老用户升级无感**：因为之前已经声明了 `<all_urls>` host_permission（用户警告"读取和更改您访问的所有网站上的数据"），新增 `tabs`（"读取您的浏览记录"）被 Chrome 的警告合并机制覆盖，不显示新警告、不触发"扩展被停用、要求重新授权"的流程。
2. **`background/KeywordService._hydrateContext`**：getKeyword 入口处，background 用 tabId **自己** `chrome.tabs.get(tabId)` 重新读一次最新 tab 元数据。前端传来的 url/title 只是参考，空就用 background 拿到的覆盖。额外用 `tab.pendingUrl` 兜底（导航中场景）。

效果：前端无论传什么，background 都先把上下文水合（hydrate）到最新真值，杜绝"前端早期空快照被当最终结果"。

#### 2. 关键字徽章切换有/无关键字时的"跳跃感"

**问题表现**：在网页选中文字 → 看到徽章弹出来；取消选中 → 徽章消失。这两个状态切换时，**侧边栏 / popup 顶部有 1-2px 的微妙跳动**。

**根因**：之前的 drawer 抽屉动画（`max-width: 0 → 240px` + `overflow: hidden`）在 Chrome 不同版本对 flex 子项（`flex-shrink: 0` 的 26px 按钮）的**高度计算存在 1-2px 差异**。看起来是宽度动画，但内部 flex 高度算法可能在动画过程中跳。

**修复**：放弃 drawer，改成**完全固定的 width + height**：
- `.sp-keyword-wrap`: `width: 200px; height: 26px` 永远不变
- `.menu-keyword-wrap`: `width: 180px; height: 26px` 永远不变
- `.sp-header`: `height: 38px` 锁死
- `.menu-header`: `height: 50px` 锁死

内部 badge + buttons 通过 `opacity` 淡入淡出（既有），但**外层 wrap 自己绝不动尺寸**，所以 header 整体的 width × height 100% 静态。

副作用：**无关键字时右侧会有 ~200px / 180px 的"虚位"**（一片空白）。这是布局完全静态的必然代价，比起跳跃感本身要好得多。

#### 3. popup 在 chrome:// 上"假成功"显示上一页旧关键字

**问题表现**：在 google.com 选过文字后，同一 tab 切到 chrome://settings/help，popup 居然显示了 google 的关键字（不是当前页的）。

**根因**：popup 的 storage 5 分钟瞬时缓存只查 tabId + TTL，不查 URL。同一 tabId 内 URL 变了，缓存仍命中、显示上一页的旧值。

**修复**：缓存写入时一起存 URL，读取时强校验。URL 不匹配视为 stale 丢弃。

### 🔧 改进

#### 关键字徽章字号微调

- 侧边栏徽章：**11px → 12px**（max-width 160px → 180px 同步上调，避免过早截断）
- popup 徽章：**12px → 13px**（max-width 120px → 140px 同步上调）

更易读，header 高度兜底足够，不影响布局。

#### 关键字获取链路 SSoT 化（C 档重构）

之前三个入口（popup / sidepanel / 右键菜单）各自拼装 `forceFetchSelection` / `skipCurrentMenuFallback` 等 boolean 旗标，语义靠注释和调用方记忆。本次统一过 **`background/KeywordService`** 门面：

```
popup.js / sidepanel.js
  ↓ shared/keywordClient.js 的 CCSKeywordClient.requestKeyword(intent, options)
  ↓ chrome.runtime.sendMessage({ action:'getKeyword', tabId, url, title, intent })
  ↓
background/events.js  ← onMessage handler
  ↓ KeywordService.getKeyword({...})
  ↓
background/KeywordService.js  ← intent → policy 表 (见 INTENT_POLICIES)
  ↓ computeSearchTextForTab(...)  ← 引擎层不动
```

意图字面量：
- `'popup-open'`        → forceFetchSelection + skipCurrentMenuFallback + 写 storage 缓存
- `'sidepanel-init'`    → 同上但不写 storage
- `'sidepanel-refresh'` → 同上
- `'contextmenu-click'` → 同上
- `'menu-preview'`      → 软策略（可读 currentMenuState 兜底）
- `'page-changed'`      → 软策略

新增第 4 个入口（比如 dockbar、命令面板）零摩擦：声明一个 intent + policy 即可。

### 🛠 技术改动

- 新增 `background/KeywordService.js`（240 行）：意图驱动门面 + storage 缓存 + `_hydrateContext` 兜底
- 新增 `shared/keywordClient.js`（115 行）：popup + sidepanel 共用客户端
- `manifest.json`：新增 `tabs` 权限
- `background/keywordResolver.js`：所有在线 candidate 失败后兜底读 `fallbackKeywordByTab[tabId]`（URL 强校验）
- `sidepanel/sidepanel.js`：refresh 加 50ms debounce + 空结果退避重试（400ms / 800ms，最多 3 次）+ 多事件触发（`url` / `title` / `status:complete`）。**注**：本次根因修复在 background 侧，这些前端重试逻辑保留作防御性冗余
- `popup/popup.js`：使用 `CCSKeywordClient.requestKeyword('popup-open', {instantFromStorage: true, onInstant: ...})` 实现"打开瞬间不空白"
- `popup/popup.css` / `sidepanel/sidepanel.css`：徽章字号 +1px、wrap 固定 width + height、header 固定 height
- `eslint.config.mjs`：注册 `KeywordService` / `CCSKeywordClient` / `KEYWORD_INTENTS` 三个新全局
- `build.sh`：`COPY_DIRS` 加 `shared/`

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- 与 v1.6.10 完全兼容；无 storage schema 改动、无新依赖、无破坏 API
- **权限变更说明**：新增 `tabs` 权限（Chrome 警告文案"读取您的浏览记录"）。**对老用户升级是静默的**——因为已有 `<all_urls>` host_permission（"读取和更改您访问的所有网站上的数据"）已经涵盖了 `tabs` 的警告，Chrome 自动合并不显示新警告、不触发停用流程。新装用户在安装对话框看到的警告列表与 v1.6.10 完全相同。
- `tabs` 权限的真实用途：在 background `KeywordService._hydrateContext` 里用 `chrome.tabs.get(tabId)` 读当前 tab 的 url/title，仅用于提取关键字。**零网络上传**、零持久化存储浏览历史。

## 已知限制

- **权限警告语境**：虽然 Chrome 升级时静默，但新装用户和阅读权限说明的老用户可能在 `chrome://extensions/[id]/` 详情页看到完整警告列表。`<all_urls>` 仍是最高警告，`tabs` 被合并不另外显示。
- **chrome:// 上仍然无法读取页面 selection**：Chrome 永久禁止 executeScript 注入内置页。本版本只解决了"拿不到 title"的问题；如果用户要在 chrome:// 上把选中文字作为关键字，需要用侧边栏顶部的「📋 从剪贴板读取关键字」按钮兜底。
- **关键字徽章"虚位"**：无关键字时右侧会保留 ~200px 空白以避免布局跳动。可以接受。

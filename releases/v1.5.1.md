# 触触搜 v1.5.1 发布说明

发布日期：2026-05-01

## 一句话总览

侧边栏新增剪贴板读取按钮兜底 chrome:// 等不支持选区的页面；修 Windows 滚动文字失效（用 RAF 替代 CSS animation）；欢迎页「打开侧边栏」按钮实时同步开关状态；popup 设置加「📖 查看欢迎页」入口；⚠️ 浮层视觉强化（amber 渐变底 + 强边框 + 光晕）。

## 主要更新

### ✨ 新功能

- **侧边栏剪贴板读取按钮**（核心新功能）：
  - 当关键字徽章为空时，侧边栏顶部自动露出「📋 从剪贴板读取关键字」按钮（虚线 amber 边框，暗示"备用入口"）
  - 用户复制文字（Ctrl+C / ⌘C）后点按钮 → `navigator.clipboard.readText()` 读剪贴板 → 写入关键字 → 菜单可正常跳转引擎
  - 关键字非空时按钮自动隐藏（不污染正常使用流程）
  - 边界处理：剪贴板为空 / 读取失败 → 按钮文字临时变 ⚠️ 错误提示，2 秒后还原
  - **解决场景**：用户在 `chrome://contextual-tasks/`（Chrome 内嵌 Google AI Mode）、Chrome Web Store 商品页等不允许 content script 注入的页面上原本完全没法用扩展，只能干瞪眼。现在多一条手动救命路径。

- **欢迎页「立即打开侧边栏」按钮实时同步状态**：
  - 用户在欢迎页点开侧边栏后如果不小心关掉，按钮会立即变回 `✨ 立即打开侧边栏` 状态——不会找不到入口
  - 从 popup、浏览器右上侧边栏按钮等任意来源开关都同步
  - 多窗口独立追踪（A 窗口的开关不影响 B 窗口的欢迎页）
  - SW 重启 / 扩展重载时欢迎页端 500ms 自动重连

- **popup 设置面板加「📖 查看欢迎页」入口**：
  - 用户首次安装的欢迎页关掉后想再看，可在 ⚙️ 设置 → 「📖 查看欢迎页」找回
  - 也是用户回顾「四种入口介绍 + 视频教程 + 作者关注 + AI 检测提醒」的常驻入口

### 🐛 修复

- **Windows 上滚动文字失效**：
  - 现象：侧边栏 ⚠️ 提醒条 + 欢迎页顶部横条的文字滚动在 Windows Chrome 上不工作，Mac 正常
  - 原因：CSS marquee 写法（`padding-left: 100%` 在 flex item + `min-width: 0` 子元素上）的百分比解析在 Windows 上有时序问题
  - 修复：完全绕开 CSS animation，改用 `requestAnimationFrame` 循环 + 实测 viewport / text 像素 + `transform: translateX(${px}px)` 手动驱动。速度按 px/秒（welcome 44、sidepanel 42），跨平台像素一致
  - 详见 `docs/archive/MARQUEE_SCROLL_WINDOWS.md`

- **手动设的关键字会被 refresh 清空**：
  - 现象：点剪贴板按钮设好关键字 → 点侧边栏菜单项 → 关键字突然变空 → 搜索引擎收到空字符串、提示获取不到内容
  - 原因：每次点击菜单项前 `refresh()` 会重新拉关键字（CLAUDE.md 文档过的"修边栏关键字滞后"机制），chrome:// 页面拉不到就把手动设的清空了
  - 修复：加 `keywordSetManually` 标志位。refresh 三段决策——URL 变了跟随新页（清标志）/ URL 没变 + 手动设过 + 自动提取空 → 保留手动关键字 / 其它情况照常覆盖

- **滚动时置顶横条 jitter**：
  - 现象：滚动 welcome 页 / 侧边栏菜单时顶部 amber 横条有亚像素浮动重绘，视觉上"波动"
  - 原因：`position: sticky` 元素每帧需要在 normal flow 与 stuck 状态间切换计算，加上 box-shadow + 滚动动画时 GPU 合成层不稳
  - 修复：改 `position: fixed`，浏览器只算一次坐标固定渲染。welcome 页 body padding-top: 60px、侧边栏 body padding-top: 82px 给 fixed 元素留位

### 🔧 改进

- **⚠️ 悬停浮层视觉强化**：
  - 改前：纯白底 + 40% 透明 amber 边框，跟侧边栏白底反差太弱，用户感觉"里面没东西"
  - 改后：浅 amber 渐变底（`#fef3c7 → #fde68a`）+ 1.5px 实心 amber 边框 + amber 光晕阴影 + 圆角从 8px 调到 10px、内边距从 10/12 调到 12/14（呼吸感更足）
  - 二级文字颜色微调，amber 底上对比仍清晰（bullets 从 `#4b5563` → `#374151`，shortcuts 从 `#6b7280` → `#4b5563`）
  - 整体效果：像一块"温暖 amber 名片"，跟白色侧边栏拉开明显对比

- **AI 检测提醒前加「关于封面生成器」**：
  - 改前：「图片生成后，建议截图另存新图再使用，避免被识别为AI产出」——读起来像在说所有搜索都要截图，容易让用户误解为通用规则
  - 改后：「**关于封面生成器**，图片生成后，建议截图另存新图再使用，避免被识别为AI产出」——前缀清楚是封面功能专属
  - 同步改 4 处：侧边栏 banner / 欢迎页顶部横条 / 欢迎页警告卡片标题 / ChatGPT prompt 头条

### 🛠 技术改动

- **欢迎页 push-based 状态订阅**：`background/events.js` 加 `welcomePortsByWindow` Map + `notifyWelcomeWatchers()` 广播；新 onConnect 分支处理 `welcome-watcher` port 名。sidepanel-alive port 增减时自动广播给同 windowId 的欢迎页订阅者。welcome 页连上后立即收到当前状态推送
- **Marquee 改 RAF 驱动**：`welcome.js` / `sidepanel.js` 各加 `setupMarquee(viewportSelector, textSelector, options)` 函数。`getBoundingClientRect()` 实测尺寸 + `requestAnimationFrame` 循环 + `ResizeObserver` 重测 + `will-change: transform` GPU 提层
- 新增 `docs/TO-BE-IMPLEMENTED/` 目录归类待开发功能提案，跟 `docs/archive/`（已解决）和 `KNOWN_ISSUES.md`（已知 bug）形成语义对仗
- 归档完整的「智能截图功能」提案到 `docs/TO-BE-IMPLEMENTED/screenshot-feature.md`（154 行）—— 含 3 种实现路径评估、Chrome API 选型、6 大边界限制、6 个决策点、实施 checklist
- 剪贴板按钮的点击 / 失败 / 状态切换都用 `reset()` 函数统一兜底，按钮 DOM 状态在 hidden 时也保持干净

## 兼容性

- Chrome 114+（Manifest V3 + chrome.sidePanel API）
- 无破坏性改动，旧用户升级直接生效
- `clipboardRead` 权限已在 v1.0 起就声明，无新增权限——升级不会触发任何商店权限提示

## 已知限制

- `chrome://contextual-tasks/`（Chrome 内嵌 AI Mode）等"陌生协议页"：URL 关键字仍然不识别（详见 `docs/KNOWN_ISSUES.md`），鼠标选区仍无法捕获（Chrome 平台层硬限制）—— v1.5.1 的剪贴板按钮就是这条路上的"手动救命"路径，不会代替选区捕获，但用户至少不再"完全没法用"
- 智能截图功能（在边栏直接点 📸 拍图层）暂未实施，提案已归档到 `docs/TO-BE-IMPLEMENTED/screenshot-feature.md`，待后续版本评估上线

## 升级提示

老用户从 v1.4.0 升级 → 主要感知：

1. **Windows 用户的 banner 文字滚动现在工作了**（Mac 用户原本就工作，无感知）
2. **新功能**：在那些原本完全没法用的页面（chrome:// AI Mode / Chrome Web Store / 部分 PDF 阅读器内部页等），侧边栏顶部会出现 📋 按钮。复制文字后点一下就能搜了
3. **欢迎页按钮实时同步**：从欢迎页打开侧边栏后误关，按钮立即恢复，不会找不到入口

5. **更稳**：滚动 welcome 页 / 侧边栏菜单时，顶部 amber 横条不再"波动"

7. **更醒目**：⚠️ 悬停浮层从白底变 amber 渐变底，"里面有内容"的视觉信号更强

# 触触搜 v1.6.43 发布说明

发布日期：2026-08-03

## 一句话总览

**X (Twitter) 搜索页关键字取错 + 单字符关键字丢失修复** —— 在 X 上搜「d」，插件读到的却是链接里的 `typed_query`；单个汉字同样受影响。

## 主要更新

### 🐛 修复

#### X (Twitter) 搜索页关键字取错

在 `https://x.com/search?q=d&src=typed_query` 这类页面上，右键菜单 / Popup / 侧边栏显示的关键字是 **`typed_query`**（链接里的来源标记参数），而不是你实际搜的「d」。

原因是插件对 X 缺少站点识别规则——虽然自带「在 X 搜索」菜单能开 `x.com/search?q=`，却读不回来，只能退到「猜哪个 URL 参数最像关键字」的兜底逻辑，结果猜中了噪声参数。现已补上 X / Twitter 的站点规则，关键字直接读 `q`，不再靠猜。

#### 单字符关键字被丢掉

兜底猜测逻辑此前会把长度小于 2 的参数值一律忽略，于是：

- 搜「d」「中」这类单字/单词 → 关键字取不到，反被无关参数顶替
- **单个汉字影响尤其明显**（中文单字搜索很常见）

现在常见关键字参数（`q` / `wd` / `query` 等）允许单字符，单个汉字、单个字母都能正常识别；纯数字单字符仍按分页参数排除（`?p=1` 是翻页，不是搜索「1」）。

除 X 外，Reddit 等同样走兜底逻辑的站点一并修好。

#### X 分享链接不再把分享码当关键字

`https://x.com/xxx/status/123?s=20` 这类分享链接，此前关键字会变成「20」（`?s=` 是分享码）。现在 X 站内除搜索页外不再从 URL 参数猜关键字，改用页面标题（推文作者 + 内容），标题末尾的「/ X」也会自动去掉。

### 🛠 技术改动

- **站点匹配从子串包含改为域名后缀匹配**：原先的 `hostname.includes('youtube.com')` 会把 `youtube.com.evil.test` 也认成 YouTube；本版新增 X 规则后，`includes('x.com')` 还会误伤 netflix.com / box.com（都含 `x.com` 子串）。跳过名单与 X 规则均改为严格后缀匹配，顺带修掉 YouTube 那条既有隐患。
- **关键字兜底打分改为分层**：常见关键字参数（`q` / `wd` / `query`…）整体优先于其它参数，噪声参数无论分数怎么调都无法越过真正的关键字；`src` 加入噪声参数黑名单。
- **回归用例**：关键字提取的 dual 校验（`npm test` / CI 自动跑）新增 9 条用例，覆盖 X 搜索页、单汉字、分享链接、钓鱼域名、纯噪声参数等场景；6 条负例逐个注入退化代码验证，均被精确抓红。

# 触触搜 v1.5.2 发布说明

发布日期：2026-05-01

## 一句话总览

封面生成器持续打磨——自定义风格升级为多行预设库 + dropdown 切换、新增 10 种主流平台比例选择、若干 UX 细节修复。

## 主要更新

### ✨ 新功能

#### 1. 封面生成器 · 自定义风格预设库

- 自定义风格从"单一文本"升级为"多行预设库"
- textarea 维护多行预设，每行=一个独立风格关键词
- dropdown 列出所有预设（前 15 字截断 + …），选哪行就用哪行
- 新增行**自动跳转选中**——多行粘贴或末尾追加时立即指到最末新行，不必手动再点
- 改 textarea 后 dropdown 智能跟随：删了当前选中行回退第一行，没删则保持选择

#### 2. 封面生成器 · 比例选择

sidepanel 置顶 picker 内新增比例 dropdown，**全局生效**（适用所有封面调用——sidepanel / 右键 / popup）。10 个预设按"宽到窄"排序覆盖国内外主流自媒体平台：

| 比例 | 主要平台 |
|---|---|
| **5:2** | 横幅封面（默认） |
| **2.35:1** | 微信公众号头图 / 电影宽屏 |
| **2:1** | 横幅卡片（Twitter / 知乎） |
| **16:9** | 通用横屏（YouTube / B 站 / 视频号） |
| **3:2** | 头条号 / 摄影标准 |
| **4:3** | 传统媒体 / PPT |
| **1:1** | 方形（Instagram / 微博 / 朋友圈） |
| **4:5** | 竖版图文（Instagram） |
| **3:4** | 竖版封面（小红书原生 / Pinterest） |
| **9:16** | 手机竖屏（抖音 / TikTok / Reels / 视频号） |

不够用？支持**自定义比例**——输入 W:H（如 `21:9` / `1.43:1`），最多保留 5 个，溢出剔除最旧。

#### 3. 模板末尾「调整自定义风格」闭环提示

ChatGPT 跳转后用户可读区追加：

> 💡 如果生成图片效果不满意，请回到侧边栏调整「自定义风格」字眼后再试（风格关键词越具体，渲染越准）。

拿到不满意结果时用户立刻知道下一步该去哪改、改什么。配合预设库可以攒多个风格方向逐个试。

### 🐛 修复

#### 自定义风格的 purpose 没注入到 prompt

之前选自定义风格时，模板里 `${purpose}` 会被 `coverPrompts.json` 里 custom 分类的占位文本替代，用户实际填写的关键词丢失。

**根因**：events.js SSoT 快速通道没把 sidepanel 传过来的 `request.purpose` 透传给 `runAITask`。

**修复**：`runAITask` 加 `purposeOverride` 参数 + `buildTaskPrompt` 优先用 override，事件层在 `cover/custom` 时显式注入。

#### 置顶卡片副标题 / dropdown 长文本挤爆容器

之前选超过 18 字的自定义风格行后，"✏️ 修改"按钮会被挤出可视区。

**根因**：`.sp-pin-action` 缺 `min-width: 0`，flex item 默认 `min-width: auto = content size`，长文本强行撑大容器，内层 ellipsis 链断在中间一环失效。

**修复**：双层防御——
- 应用层：truncate 统一到 15 字（`CUSTOM_LINE_PREVIEW_MAX = 15`，dropdown 选项与卡片副标题共用）
- CSS 层：给 `.sp-pin-action` 补 `min-width: 0` 让 ellipsis 真正生效

#### 操作自定义编辑区不自动激活 custom 模式

之前用户在 picker 改 textarea 或选 dropdown 后保存，可能因为 radio 没切到"自定义"而改动不生效。

**修复**：textarea oninput / dropdown onchange 都调 `activateCustomCategory()`，自动切 radio + 同步 UI；`rebuildCustomDropdown` 末尾加 `sel.value = chosen` 显式同步，防浏览器在 innerHTML 重建后 selectedIndex 残留默认 0 的 quirk。

### 🔧 改进

- **置顶卡片图标** 📌 → 🎨：原图钉视觉脱离"封面生成器"语义，改为调色板与全项目封面生成器统一标识对齐。

### 🛠 技术改动

- `prompts/coverPrompts.json` 模板把硬编码 `5:2` 改为 `${ratio}` 占位；新增 `custom` category。
- `AITaskRegistry.buildTaskPrompt` 加通用 `options.vars` 机制——未来加任意模板变量直接通过 `vars` 传入，无需改 schema。
- `AITaskHandler.runAITask` 内部抽出 `collectTaskVars(taskId)`——cover task 自动从 `chrome.storage.local` 读 ratio，三端调用方都不用关心透传，**单一数据源**。
- 新增 storage keys：
  - `ccs_cover_aspect_ratio`（当前比例）
  - `ccs_cover_custom_ratios`（自定义比例数组，最多 5 个）
  - `ccs_cover_custom_selected_line`（自定义风格当前选中行）
- `PinnedAction.lastDropdownLines` 字段记录上次 rebuild 行集合，支撑"自动跳新行"逻辑。
- README.md 功能特性段重写——完整反映 v1.2.0+ 至今所有新功能。
- `releases/store-listing.txt` 新建——长期单一文件，每次发版前覆盖式更新；旧的 `store-listing-v1.2.0_*.txt` 保留为历史归档。

## 兼容性

- Chrome 114+（Manifest V3 + chrome.sidePanel API）
- 与 v1.5.1 完全兼容，旧用户升级直接生效
- 旧版本只有 `customPurpose` 单字段的用户，init 时把它解析成首行作为 `customSelectedLine` fallback，平滑升级

## 已知限制

- 自定义风格预设库目前最多 600 字符 textarea 容量
- 自定义比例最多保留 5 个，溢出自动剔除最旧
- 比例选择仅适用封面生成器，其它 AI 任务（速答 / 百问 / 优化提示词）不受影响

## 升级建议

强烈建议老用户升级 —— 修复了 v1.5.1 自定义风格 purpose 注入的关键 bug，自定义风格在 v1.5.1 上是 broken 的（生成出来的封面与用户输入不符）。

# 触触搜 v1.12.1 发布说明

发布日期：2026-09-02

## 一句话总览

**扩展升级后，已经开着的 X / 知乎页面上的速答按钮不再变成点不动的死按钮** —— 改为明确提示刷新，并且绝不擅自替你刷新。

## 主要更新

### 🐛 修复

#### 升级后旧页面上的速答按钮不再点不动

Chrome 会在后台静默升级扩展，但**不会刷新你已经打开的标签页**。升级完成后，旧页面里跑着的内容脚本扩展上下文立刻失效，可它此前插入的闪电按钮还好端端留在 X / 知乎页面上。此前点下去只会得到一句 `runtime-unavailable`——看不懂，也不知道该做什么。

现在新版本在升级时会主动给这些旧页面装一个**轻量守卫**：

- 接管旧按钮的点击，弹出「扩展已升级，请刷新当前页面后继续使用速答。」并给出「刷新页面 / 稍后」两个按钮
- **不会未经允许自动刷新**。你在 X 编辑器里没发出去的草稿、知乎写了一半的回答都不会因为升级而丢
- 守卫只针对版本标记缺失或与当前版本不符的旧按钮；你刷新之后，正常加载的新版按钮不会被它拦截
- 选「稍后」提示会关掉，按钮仍处于「需刷新」状态，随时可以再点

#### 上下文失效类报错统一成人话

`Extension context invalidated`、`Receiving end does not exist`、`Could not establish connection`、`message port closed` 这一类浏览器内部错误，现在一律显示为「扩展刚完成升级，请刷新当前页面后再试」，不再把原文抛给用户。其它错误照常显示原始信息，便于排查。

### 🛠 技术改动

- 共享速答运行时给每个注入按钮打上 `data-ccs-site-fastqa-version` 版本标记；新增 `toUserFacingError()` 与 `runtimeUnavailableMessage` 导出，`runtime-unavailable` 分支改为返回 `code: 'EXTENSION_CONTEXT_INVALIDATED'` 加中文文案。TypeScript 与 legacy 生产脚本双轨同步。
- `background/events.js` 在 `chrome.runtime.onInstalled` 的 `update` 分支调用新增的 `ccsInstallSiteFastQaUpdateGuards()`：用 `chrome.tabs.query` 找出 x.com / twitter.com / zhihu.com 的已开标签，再用 `chrome.scripting.executeScript` 注入一个完全自包含（可被序列化）的守卫函数。守卫用 `MutationObserver` 跟进后续新增/属性变化的按钮，click 事件在捕获阶段拦截并 `stopImmediatePropagation()`。重复注入时同版本实例会被复用、旧版本实例先 `dispose()`。
- 注入结果经 `Promise.allSettled` 汇总，成功/失败数写入 `logMenuEvent('site-fastqa-update-guards')`；单个标签注入失败（如权限受限页）不影响其余标签，整体异常也只记日志、不抛出。
- 冒烟新增「扩展升级守卫」全链断言：夹具初始化 → 旧按钮被接管 → 弹出中文刷新提示 → 不泄露 `runtime-unavailable` → 刷新后新版按钮恢复 → 守卫自身零未捕获异常。`verify:x-tweet-fastqa` 另加 6 条源码级断言，强制运行时必须给按钮打版本标记，且不得再返回裸 `runtime-unavailable`。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**（`scripting` 与 x/zhihu 主机权限本就已有）、无存储结构变化、无服务器依赖、无新增站点匹配
- 未删除任何菜单项或入口；右键菜单、Popup、侧边栏、Google Docs 改写、ChatGPT 长文动作行为均不变
- 守卫仅注入 x.com / twitter.com / zhihu.com 的已打开标签，且仅在扩展**升级**时触发；首次安装与浏览器启动都不会触发

## 已知限制

- 沿用 v1.12.0 已知限制
- 守卫只覆盖升级发生**当时**已经打开的 X / 知乎标签。若某个旧标签当时处于被丢弃（discarded）状态、之后才被唤醒，仍可能出现旧按钮无守卫的情况——此时点击会看到统一后的中文提示，刷新即可
- 页面自身的 CSP 不影响该守卫（走 `chrome.scripting` 注入），但如果标签处于扩展无权访问的页面（如 `chrome://`），注入会被跳过

## 升级提示

- 从 v1.12.0 升级：**这一版的效果要等下一次扩展升级时才看得到**——即从 v1.12.1 升级到之后的版本时，旧页面上的按钮会给出刷新提示而不是报错
- 本次由 v1.12.0 升上来时，你手上已经开着的 X / 知乎页面里仍是 v1.12.0 的旧按钮（那一版还没有守卫），照旧手动刷新一下即可
- 其余功能与 v1.12.0 完全一致
- **上架说明**：本版为纯修复，不新增商店描述，沿用 [releases/v1.12.0.md](./v1.12.0.md) 的「商店描述」段。若商店线上版本仍停留在 v1.8.0（v1.9.0 / v1.10.0 / v1.10.1 / v1.11.0 / v1.12.0 均未上传），请把 [releases/v1.9.0.md](./v1.9.0.md)、[releases/v1.11.0.md](./v1.11.0.md) 与 v1.12.0 的商店描述合并后再发布——否则长文工作流那批大功能对商店用户是首次可见却没有任何说明。

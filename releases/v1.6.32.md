# 触触搜 v1.6.32 发布说明

发布日期：2026-06-09

## 一句话总览

**修侧边栏 / popup 冷启动时 chrome://extensions 刷出 `getKeyword` TIMEOUT 警告** —— 把 best-effort 关键字拉取的超时预算放宽到冷启动容忍档，警告大幅减少，功能此前本就不受影响。

## 主要更新

### 🐛 修复

#### 冷启动 `getKeyword` 超时警告

**症状**：在 chrome://extensions 的"错误"列表里看到类似：

```
[extension][runtime][timeout][getKeyword-xxx] getKeyword
[extension][keyword][request-failed][getKeyword-xxx] TIMEOUT
```

**根因**：打开侧边栏 / popup 时，如果 Service Worker 正处于**冷启动**（刚被唤醒，需要先 eval 打包产物 + `importScripts` 多个 legacy 模块 + 挂 bridge，然后才跑 `KeywordService`），原本"新鲜关键字"拉取的预算是 **1200ms / 不重试**——冷启动来不及，于是超时；而后台自身的安全兜底响应窗口是 2500ms，客户端 1200ms 就先放弃了。超时被 logger 以 `warn` 记录，chrome://extensions 会把 warn 也列为"错误"。

**为什么功能此前不受影响**：这条拉取是 **best-effort 新鲜值**。首屏关键字徽章一直由两层兜底覆盖——① 打开时先读 `ccs_kw_<tabId>` storage 缓存即时渲染；② 挂 `storage.onChanged` 监听，接住后台稍后写回的值。所以即使这条超时，徽章照常显示，只是"那一次主动拉取"失败了。

**修复**：把 best-effort 路径的超时放宽到**冷启动容忍档**——`3000ms`（≥ 后台 2500ms 安全兜底响应）+ `1` 次重试。SW 已热时（切标签等场景）后台 <100ms 就回，放宽的超时根本不触发，**无变慢副作用**；缓存命中场景仍保持 snappy（900ms / 不重试）。涉及三处：

- 侧边栏 `getCurrentKeyword`（init 空缓存 + tab 切换刷新）
- popup 后台刷新关键字（cache miss 时）
- popup `getSidePanelState` 侧栏状态校正（同属冷启动期 best-effort）

## 兼容性

- Chrome 114+（不变）
- Manifest V3
- 用户已有数据全部兼容
- **改动范围**：`sidepanel/sidepanel.js` + `popup/popup.js` 的超时参数，重新生成两个运行时 bundle。不动 storage schema、不动菜单结构、不动菜单消息协议、不动后台逻辑。

## 已知限制

- 极端情况下（SW 冷启动 > 3000ms，低配机 + 大量并发）仍可能偶发一次超时警告——这是合理信号，不做全局静音以免掩盖 `executeMenuAction` 等真正需要关注的超时。
- **Grok 偶发换行闪烁** / **文心一言提交后提示词驻留**：沿用前版已知限制，后续跟进。

## 升级提示

- 从 v1.6.31 升级：商店推送后浏览器自动更新即可
- 主观感受：chrome://extensions 的"错误"列表里冷启动期的 `getKeyword TIMEOUT` 警告基本消失；侧边栏 / popup 冷启动时关键字徽章到达更稳
- 其它行为完全不变（封面默认风格仍为 v1.6.31 的「极简的留白」）

完整商店描述沿用 v1.6.20 大版本（本版为 patch：仅修冷启动超时噪声，无 UI 结构改动、无新功能、无新菜单项）。

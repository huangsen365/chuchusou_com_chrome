# 触触搜 v1.6.29 发布说明

发布日期：2026-05-21

## 一句话总览

**修富文本编辑器（含图片）Ctrl+A 全选后偶尔跳回 HTML 标题的问题**，特别是慢速释放快捷键场景下基本必现的退化，本版双层加固护住捕获的完整正文。

## 主要更新

### 🐛 修复

#### 富文本+图片 Ctrl+A 全选关键字退化

**症状**：在公众号后台、Notion、知乎专栏、飞书文档、Medium 等富文本编辑器里，对**包含图片的文章**做 Ctrl+A 全选后打开扩展 popup/sidepanel，关键字徽章偶尔从完整正文跳回 HTML 页面标题。

**触发场景**：
- 编辑器把图片渲染成 `<div contenteditable="false">` 这种"打断 DOM 选区"的节点
- 用户**慢速释放快捷键**（先放 A 后放 Ctrl，或反过来，中间间隔超过 100ms）
- 慢释放时几乎必现；快释放偶尔幸运不复现

**根因（两条独立链路叠加）**：

1. **content.js 端**：Ctrl+A 触发后 0ms / 150ms 两次 flush 用启发式 Tier 4 拿到了完整正文（跨过图片的 textContent），但**后续 keyup 事件**也会触发 200ms 防抖→ `applySelection(readCurrentSelection())`。`readCurrentSelection` 只有 Tier 1 标准 selection.toString()，富文本+图片里只能拿到被图片打断的半截，直接覆盖了 Tier 4 的长文本。慢释放 = keyup 多次触发 = 多次覆盖。

2. **background 端**：content.js 即使拦住了，老 selectionChanged handler 对所有非空消息都接受。如果某些边界情况绕过 content.js 的闸（DOM mutation、focus 切换等），BG 就会写进 storage cache，prefetch 跟着把 HTML 标题写回去，下次 popup 打开就退化了。

**修复**：双层防御。

**Layer 1（content.js）**：把"Ctrl+A 防退化保护窗口"从隐式的时间戳推算改成**显式状态**：
- 新增 `selectAllProtectUntil` 绝对截止时间戳 + `selectAllKeyActive` 按键活跃状态
- **关键改进**：keyup handler 里只要 `selectAllKeyActive=true` 就调用 `extendSelectAllProtect()` 续期保护窗口——用户按住多久、慢释放多久，窗口跟着多久
- `isSelectAllDegradation()` 判定规则：保护期内 + 已有较长选区 + 新值空或更短 + 触发源非 mouseup/contextmenu/init/keyup:Escape/keyup:Enter → 拒绝

**Layer 2（background）**：content.js 的 `selectionChanged` 消息新增 `trigger` / `selectAllProtected` / `selectAllProtectUntil` 字段。BG 收到后做同款判断，即使 content.js 漏拦，BG 也能挡掉退化消息（不写 selectedTextByTab，不跑 prefetch）。

#### `fetchSelectionSnapshot` 也尊重保护期

popup/sidepanel 主动拉选区快照时，如果保护期内的活选区比已保存的 protected state 更短，强制返回 protected state，新 source 标记为 `'protected-state'`。之前会用半截活选区覆盖完整内容。

#### `applySelection` 的小漏洞修复

之前即便 gate 拒绝（return 提前退出），`window.selectedText` / `window.lastNonEmptySelection` 这两个全局变量已经被赋值了。现在把它们的赋值挪到 gate 之后，拒绝时全局也不动，避免其它模块读到错误状态。

### 🛠 技术改动

- **新增 `scripts/verify-select-all-protection.mjs`**（239 行）—— headless Chrome + CDP 的集成测试。注入构造好的"文字 + 图片 + contenteditable=false"DOM，模拟完整链路：
  1. `dispatchEvent` Ctrl+A keydown → 断言 selectionChanged 消息包含「第二段」「第三段」（图片后的文字）
  2. 清空 DOM selection + dispatch keyup 'a'（模拟慢释放）→ 断言 BG **没收到**空消息
  3. 调 `fetchSelectionSnapshot` → 断言 `source === 'protected-state'`
  4. mousedown → mouseup（用户主动清空）→ 断言这一次**确实**发了空消息
  - `npm run verify:select-all-protection` 单独跑，是回归保护的硬门
- `selectionChanged` 消息体新增 3 个字段供 BG 二层闸使用
- content.js 抽出 `extendSelectAllProtect` / `isSelectAllUserInitiatedTrigger` / `isSelectAllDegradation` 三个 helper

## 兼容性

- Chrome 114+（不变）
- Manifest V3
- 用户已有数据全部兼容
- **改动范围**：`content.js` + `background/events.js` + 新增一个 verify 脚本。不动 storage schema、不动菜单、不动菜单消息协议。

## 已知限制

- 极端边界场景（用户按住 Ctrl+A 超过 30 秒不放）：保护窗口理论上会一直续期，但实测无影响——keyup 之后窗口也会自动 3 秒后失效，符合"用户停止动作后回归正常"的语义
- 当编辑器使用纯虚拟 DOM / 完全不操作 DOM Selection API（如 Monaco editor）时，Tier 4 启发式可能拿不到内容；这种编辑器在 v1.6.28 也是同样表现，本版不引入新问题

## 升级提示

- 从 v1.6.28 升级：商店推送后浏览器自动更新即可
- 主观感受变化：富文本编辑器里 Ctrl+A 之后打开 popup/sidepanel，**徽章一直显示完整正文，不再跳回标题**——特别是慢手用户感受最明显
- 其它场景（纯文本、URL 搜索结果页、普通文章页）行为完全不变

完整商店描述沿用 v1.6.20 大版本（纯 patch 修选区退化 bug，无 UI 改动无新功能）。

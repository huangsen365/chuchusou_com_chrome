# 触触搜 v1.6.39 发布说明

发布日期：2026-07-10

## 一句话总览

**文心一言入口链接瘦身（去掉 `enter_type=yiyan_site` 参数）+ CI 稳定性根治** —— 用户侧行为不变的清理版。

## 主要更新

### 🔧 改进

#### 文心一言入口链接更干净

所有文心相关菜单（AI 对话 / 速答 / 百问 / 优化提示词）打开的链接从 `https://chat.baidu.com/?enter_type=yiyan_site` 简化为 `https://chat.baidu.com/`。`enter_type` 只是入口来源统计标记，与页面功能无关：文心引擎识别一直按域名判定，去掉参数后落点页面、后台中转（storage relay）与选中文字自动填入行为完全不变。

- 旧 `yiyan.baidu.com` 链接的自动迁移逻辑同步更新（迁移后不再补该参数）
- 存量带旧参数的链接依旧按域名正常识别，完全兼容

### 🛠 技术改动

- **CI 偶发红根治**：headless Chrome 冷启动等待 `DevToolsActivePort` 的 10 秒硬超时改为环境可调（CI 45 秒 / 本地 15 秒，`CHROME_DEVTOOLS_PORT_TIMEOUT_MS` 可覆盖），三个 Chrome 校验共用；CI 的 `npm test` 另加 3 次重试兜底残余抖动
- **发版不再重复跑 CI**：workflow 只在分支推送时触发，tag 推送不再多跑一次全套 CI
- 三个校验脚本（shared-config / url-safety / extension-smoke）的文心 URL 契约同步收紧：断言 `enter_type` 不再出现，防止参数回潜；dedupe 校验保留旧参数输入以持续覆盖存量旧格式 URL 的兼容路径

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **改动范围**：文心引擎 URL（config/prompts 及镜像）、AI prompt relay（`chatgptPromptRelay.js` 一行删除）、events.js / menuHandlersAttach.ts 的 fallback URL、CI workflow 与校验脚本。不动 storage schema、消息协议、其他引擎、UI

## 已知限制

- 沿用 v1.6.38 已知限制：文心新入口 `chat.baidu.com` 的真实填充效果依赖百度页面的输入框结构，自动化冒烟已验证中转管道与新域名契约，真站实际填充以真实页面为准

## 升级提示

- 从 v1.6.38 升级：商店推送后自动更新即可
- 用户几乎无感：点「文心一言」打开的地址栏少了一段 `?enter_type=yiyan_site`，其余体验不变

完整商店描述沿用 v1.6.20 大版本（本版为清理 + CI 改动，无新增功能、无新权限）。

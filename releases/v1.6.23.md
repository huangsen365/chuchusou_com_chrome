# 触触搜 v1.6.23 发布说明

发布日期：2026-05-18

## 一句话总览

**修复 popup 4 个子分类菜单点击无响应（v1.6.19 静态化菜单的回归 bug）+ 进一步缓解新打开网页时 popup 慢（storage 缓存同步链路打通）+ 新增 🩺 一键诊断工具**。

## 主要更新

### 🐛 修复

#### 1. popup 子分类菜单点击不展开（v1.6.19 回归 bug）

**症状**：点击 popup 里"💯 触触搜百问 / ⚡ 速答壹拾佰 / 🧠 优化提示词 / 🎨 封面生成器"4 个 has-children 顶级项时，子菜单不展开，没有任何反馈。

**根因**：v1.6.19 把菜单从 JS 渲染改成 prebuild 静态 HTML 后，popup.js 的 click 事件代理只保留了"点叶子项执行操作"分支，**丢失了"点 has-children 父项调用 `toggleSubmenu` 展开/折叠"分支**。所有点击统一走 `handleClick` → 发 `executeMenuAction menuType='submenu'` 给 SW → SW 不处理 submenu 类型 → 静默丢消息。

**修复**：在 click delegation 里加 `if (itemEl.classList.contains('has-children')) { this.toggleSubmenu(...) }` 分支。

#### 2. 子菜单展开时底部子项被裁掉

**症状**：当用户连续展开"🧠 优化提示词"下面多个 level-2 二级分类（如同时展开"深度研究 + 普通对话 + 代码编写"），最底下的几个子项会被切掉看不到。

**根因**：CSS `.submenu { max-height: 800px }` 是 transition 用的上限。优化提示词 8 个分类全展开极端情况下内容 ~1800px，被 800px box 高度限制裁掉。

**修复**：把展开状态的 `max-height` 从 800px 调到 5000px，覆盖所有实际场景。外层 popup body 自己的 `overflow-y: auto` 仍负责整体滚动。

### 🔧 改进

#### 新打开网页 popup / sidepanel 关键字徽章首屏立即显示

**之前的问题**：
- 用户在页面选文字 → content.js 发 `selectionChanged` 给 SW → SW 只写 `selectedTextByTab[tabId]`（**内存**）
- 新 tab 加载完 → SW 触发 `prefetchMenuState` → 算出 URL/title 关键字 → 只写 `fallbackKeywordByTab[tabId]`（**内存**）
- popup / sidepanel 一打开 → 读 `ccs_kw_<tabId>` **storage** cache → **永远 miss**（没人往这个 key 写过）
- 退到 sendMessage 兜底链 → 等 SW 唤醒 + round-trip → 300-1500ms 后徽章才出现

**修复**：两条路径都同步往 storage 写一份关键字。popup / sidepanel 下次打开（甚至当前打开着）都能立刻从 storage 读到，**不再依赖 SW 醒着**。

```js
// background/events.js prefetchMenuState
if (keywords) {
  fallbackKeywordByTab[tabId] = { ... };  // 既有内存
  KeywordService._writeStorageCache(tabId, {  // 新增 storage 同步
    text: normalized, raw: keywords, url
  });
}

// background/events.js selectionChanged handler
if (hasContent) {
  selectedTextByTab[tabId] = { text: rawText, url };  // 既有内存
  KeywordService._writeStorageCache(tabId, {  // 新增 storage 同步
    text: normalizedSelection, raw: rawText, url
  });
}
```

URL 一起入库，`readInstantCache` 强校验，TTL 5 分钟，URL 不一致或过期自动 stale 回退到 sendMessage 路径——不会让旧值假冒新 keyword。

### ✨ 新功能（藏在设置面板里）

#### 🩺 一键诊断

设计目的：让低配 Windows 用户报告问题时，能一键提供完整诊断信息——比手动跑 `chrome://gpu` + DevTools Performance + 手抄 console 全是降维。

**怎么用**：
1. 在你卡顿的场景下打开 popup（点扩展图标即可，加载慢没关系——录像从 popup.js 顶层就开始了）
2. ⚙️ 设置 → 🩺 一键诊断
3. 看到 toast `诊断信息已复制 (XKB)，粘贴给开发者即可`
4. 粘贴到聊天或 issue 给开发者

**收集了什么**（Markdown 报告，~5-15KB）：

| 节 | 内容 |
|---|---|
| 1. 环境 | Chrome 版本 / UA / `deviceMemory` / `hardwareConcurrency` / 网络 / 屏幕分辨率 / 时区 |
| 2. GPU / 硬件加速 | WebGL `UNMASKED_RENDERER_WEBGL` 字串 + 自动判 SwiftShader 软件渲染 |
| 3. SW 连通性 | popup → SW round-trip 毫秒数（含冷启）+ 时钟同步 |
| 4. Performance 时间线 | 所有 `performance.mark` / `measure` / navigation timing |
| 5. 主线程长任务 | 录像期间所有 >50ms 长任务（PerformanceObserver） |
| 6. 控制台错误 | 最近 50 条 console.error/warn + window error + unhandledrejection |
| 7. 扩展状态 | 白名单 storage（不含选区 / 黑名单等敏感数据）+ 活跃 tab（URL 去 query） |
| 8. manifest 摘要 | 版本 / 权限 / 最低 Chrome 版本 |

**隐私边界**：
- 不收集页面文本 / 用户选区 / 浏览历史
- storage 走白名单（只读 `enabled` / `ccs_debug` / `ccs_voice_enabled` / `ccs_sidepanel_pinned_action` / `ccs_cover_aspect_ratio` / `ccs_cover_custom_selected_line`）
- 活跃 tab URL 去掉 query string + hash

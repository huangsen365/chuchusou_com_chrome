# 触触搜 v1.6.9 发布说明

发布日期：2026-05-15

## 一句话总览

popup 置顶封面卡片右下角新增「📑 改风格 / 比例 → 侧边栏」副链接 —— 极轻量、不抢主按钮焦点，把"我怎么换风格 / 改比例"这个问题精准导流到侧边栏的完整 picker。**无破坏改动、无 storage schema 变化、无新依赖。**

## 主要更新

### 🔧 改进

#### Popup 置顶卡片新增「📑 改风格 / 比例 → 侧边栏」副链接

之前 sidepanel 的置顶卡片有三件事可做：

- 主按钮：用当前风格 + 关键字一键生成封面
- ✏️ 编辑：打开 picker 切风格 / 比例 / 自定义预设
- ⓘ 说明：popover 解释文字篇幅建议、风格/比例从哪改、等等

popup 的置顶卡片**只有主按钮**，缺后两者。结果是：

- 用户在 sidepanel 配过一次后，回头打开 popup 只想"按一下生成"——主按钮足够
- 但万一想顺手换风格 / 改比例，popup 里**没有任何入口**，得自己回头去打开侧边栏

v1.6.9 起，popup 置顶卡片**右下角**多一行极轻量副链接：

```
┌───────────────────────────────────────┐
│                              5:2     │ ← 当前比例（不变）
│  🎨 封面生成器 二次元可爱            │ ← 主按钮（不变）
│                  📑 改风格 / 比例 → 侧边栏 │ ← 新副链接
└───────────────────────────────────────┘
```

视觉调性：

- 10px 琥珀色（`#92400e` opacity 0.6），与卡片本身的暖色调和谐
- 默认半透明、hover 不透明 + 加下划线，提示可点
- `align-self: flex-end` 靠右，与左上的主按钮、右上的比例数字三角呼应
- 不抢主按钮焦点

#### 为什么不加 ✏️ 编辑按钮 / ⓘ 说明？

- **✏️ 编辑**：sidepanel 的 ✏️ 点开是完整的风格/比例 picker（5 种风格 + 11 种比例 + 自定义预设 + 自定义比例），360px 宽的 popup 塞不下。要么阉割成"点 ✏️ 跳侧边栏"——那就跟 footer 的「📑 打开侧边栏」重复且更绕；要么在 popup 重做一套 picker——工作量大、还会稀释主按钮焦点。
- **ⓘ 说明**：popover 本身只是一段静态文字（文字篇幅建议、风格/比例从哪改、文字来源），技术上塞进 popup 没难度；但 popup 的主要受众是**已经从侧边栏配过、来按主按钮的回头客**，他们大概率已经看过这段说明，加上去边际收益不大。

副链接是这两个方案的中点：比 ✏️ 阉割版更轻、比 ⓘ 说明版更对症地回答用户"我怎么改"。

### 🛠 技术改动

- **`popup/popup.html`**：`#popupPin` 内主按钮后新增 `#popupPinOpenSidepanel` 按钮（`type="button"`，自带 title="到侧边栏切换风格 / 比例 / 自定义预设"）
- **`popup/popup.css`**：
  - `.popup-pin` 改 `flex-direction: column`、gap 4px、底 padding 12px → 6px
  - 新增 `.popup-pin-hint`：`align-self: flex-end`、`font-size: 10px`、`color: #92400e`、`opacity: 0.6`，hover 时 opacity 拉到 1 + 加下划线
- **`popup/popup.js`**：`bindPinnedCover()` 里给 `#popupPinOpenSidepanel` 绑点击，handler 复用已存在的 `openSidePanel()`（带 windowId / tabId 两层 fallback），零新逻辑
- 改动文件：`popup/popup.html` / `popup/popup.css` / `popup/popup.js`

## 兼容性

- Chrome 114+（Manifest V3 + `chrome.sidePanel` API）
- 与 v1.6.8 完全兼容；无 storage schema 改动、无新依赖
- 老用户升级后看到的差异：popup 置顶封面卡片右下角多一行小字「📑 改风格 / 比例 → 侧边栏」，点击直接打开侧边栏
- 主按钮交互、当前风格 / 比例显示完全不变

## 已知限制

- 副链接是单向引导（popup → 侧边栏），改完风格后需要用户自己回来 popup 再按主按钮——这是设计内行为，popup 本来就定位"快速触发"
- 副链接点击不会保留 popup 的打开状态（chrome 的限制：`sidePanel.open` 后 popup 会自动关闭）

- 商店上架审核通过后，新装用户即可在 popup 置顶卡片看到副链接

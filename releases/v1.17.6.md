# 触触搜 v1.17.6 发布说明

发布日期：2026-09-21

## 一句话总览

**AI 填入后不再误报「似乎未发送成功」** —— 发送后驻留侦测只认真正的发送动作，只在确实没进展时才补救。

## 主要更新

### 🐛 修复

#### 已经发出去了，却弹「似乎未发送成功」

**症状**：触触搜把提示词填进 ChatGPT / Claude / 文心等站点的输入框后，用户点发送或按 Enter，偶尔会弹出「似乎未发送成功：已重新同步输入框，请再点一次发送」，但消息其实已经发出去了；有时用户只是点了页面上别的按钮、或在中文输入法里按 Enter 选词，也会触发。

**根因**：发送后驻留侦测（为文心历史上「提交后提示词驻留」问题加的兜底）把**任意按钮点击**都当成发送、把**任何 Enter** 都当成提交；只要输入框里还留着提示词，就断定站点内部状态没同步，重新派发输入事件并弹提示。

**现在**：
- 只认真正的发送控件：与输入框同一 `<form>`（或无表单时同一局部容器，不把页面其他位置的按钮算进来），且带 send / submit / 发送 / 提交 语义、或站点的 `data-testid="send-button"` / `fruitjuice-send-button`，或表单内 `type="submit"`；禁用 / busy 状态的按钮不算
- Enter 只在非 Shift、非 Alt、非输入法合成（`isComposing` / keyCode 229）、非长按重复时算提交
- 补救只在这些条件同时满足时才做：还是同一个输入框且仍在页面上、URL 未变、内容自手势起一字未变、没有「停止生成」等处理中迹象、发送按钮仍存在且仍是发送按钮
- 提示文案改为「已尝试重新同步输入框；请先确认是否已发送，未发送再重试」，不再断言「未发送成功」

### 🛠 技术改动

- `content.js`：新增 `isAIPromptSendButton(button, composer)` 与 `hasAIPromptSendProgress(composer, button)`；侦测记录新增 `gesture`（`send-button` / `composer-enter`）、手势时文本与 URL；诊断日志改为「检测到发送后提示词仍在输入框，已尝试重新同步」。
- `verify:ai-fill-ux` 新增两组断言：非发送控件、其他表单的发送、中文选词 Enter 不触发再同步或诊断；站点仍在处理、输入框被替换、用户正在编辑时不触发旧任务补救。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增站点匹配、无新增文件

## 已知限制

- 沿用 v1.17.5 已知限制
- 站点若把发送按钮放在输入框表单之外且无语义标签，侦测会当作「无发送控件」而不做补救（不影响正常发送，只是少了这层兜底）

## 升级提示

- 从 v1.17.5 升级：填入后正常发送不会再弹提示；已打开的 AI 站点页面需刷新一次才会加载新内容脚本
- 其余功能与 v1.17.5 一致
- **上架说明**：本版为修复，不新增商店描述，沿用 [releases/v1.16.0.md](./v1.16.0.md) 的「商店描述」段与上架提醒。

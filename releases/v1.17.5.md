# 触触搜 v1.17.5 发布说明

发布日期：2026-09-21

## 一句话总览

**「注入X草稿 / 生成封面」支持没有 writing block 的普通 ChatGPT 回复；同轮空消息不再吃掉按钮。**

## 主要更新

### 🐛 修复

#### 长文以普通回复输出时按钮不出现

ChatGPT 并不总把长文放进 writing block，有时直接作为普通回复输出。此前触触搜只认 writing block，这种情况下「注入X草稿 / 生成封面」不会出现。

现在：同一轮回复里只有一篇文章、正文是含**唯一主标题**的 `.markdown` 时，也识别为长文成品；按钮挂在该轮回复的「复制」按钮旁，标题取正文里的 H1。同轮出现多篇文章时不替用户选择投递哪一篇，按钮不出现。writing block 路径行为不变。

#### 同轮空的 assistant 占位节点导致按钮被误删

ChatGPT 有时在一轮回复里附带空的 assistant 消息节点。此前按钮按单条消息判断，后面的空节点会被当成「不是长文」而触发清理，把前面刚挂上的按钮删掉；「选 A 改写」按钮同样受影响；来源识别也可能把空节点当成上一条消息。

现在两组按钮都按**整轮**判断：空节点不影响识别、不触发清理；来源（上一条用户提示词）定位时跳过同轮消息，但不会越过别的轮去借用更早的提示词；「生成中」判断按整轮看；按钮若被页面结构变化挪走会自动归位到「复制」按钮旁。

### 🛠 技术改动

- `modules/longArticleActions.js`：`TURN_SELECTOR` / `RESPONSE_COPY_SELECTOR`；动作栏改为 `actionGroups: Map<assistant, actions>` 持有（普通回复的动作栏在 assistant 节点外）；`workflowCandidateFor` 允许 0 个 writing block 时回退到 `.markdown h1` 文章；`extractArticleSnapshot` 对非 writing block 直接以正文为编辑器并要求恰好一个 H1；`previousUserMessage` 跳过同轮；`isStreaming(turn || assistant, …)`；`sanitizeBody` 排除自身动作条；断开的 assistant 节点统一清理。
- `modules/chatGptSelectARewrite.js` + `src/content-modules/chatGptSelectARewrite.ts`：按 `conversation-turn` 注入，整轮任一消息匹配即挂按钮，已有按钮不在复制按钮后时自动归位。
- 测试：新增 `scripts/lib/verify-plain-article-actions.mjs`；`verify:extension-smoke` 新增普通回复注入与空占位节点两组断言。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增站点匹配、无新增运行时文件
- 长文页按钮的工作流识别标记（上一条用户提示词的 4 个标记）未变

## 已知限制

- 沿用 v1.17.4 已知限制
- 普通回复路径要求正文恰好一个 H1 主标题；ChatGPT 若不输出 H1（例如以粗体行代替标题），按钮不会出现
- 同轮多篇文章时按钮不出现，属有意设计（不替用户选择投递哪一篇）

## 升级提示

- 从 v1.17.4 升级：长文以普通回复形式输出时也会看到「注入X草稿 / 生成封面」；已打开的 ChatGPT 页面需刷新一次才会加载新内容脚本
- 其余功能与 v1.17.4 一致
- **上架说明**：本版为修复，不新增商店描述，沿用 [releases/v1.16.0.md](./v1.16.0.md) 的「商店描述」段与上架提醒。

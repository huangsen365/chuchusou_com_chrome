# 触触搜 v1.6.22 发布说明

发布日期：2026-05-18

## 一句话总览

**Popup / Side Panel 低配设备打开慢的系统性优化版**。首屏只做必须的事，所有可推迟的（语音模块、封面快捷卡片、保活长连接、菜单标题刷新）全部错峰到 idle，sidepanel JS 解析体积减 21.5%，常驻 marquee rAF 加双闸门，新开网页时 SW 忙窗口从 3-6s 收窄到单次事件。

## 主要更新

### 🔧 改进

#### 1. 侧边栏首屏 JS 解析体积 -21.5%

`sidepanel/sidepanel.js` 73KB → **57KB**。把语音模块（`VoicePanel` + `OffscreenSpeechRecognizer` + 13 引擎别名表 + Levenshtein 编辑距离 + 声学×别名×历史频次融合排序，共 ~500 行）整体拆到 `sidepanel/voice.js`（20KB），**HTML 不 eager 引用**。

加载策略：
- 用户没开语音（默认）：voice.js 一辈子不下载、不解析
- 用户开了语音但没点 🎤：voice.js 仍不下载
- 用户开了语音 + 真的点了 🎤：动态 `<script>` 注入 voice.js（~20-30ms）→ 构造 `VoicePanel` → 调 `start()`

绝大多数用户从不使用语音功能，首屏完全不再付这部分代码的 V8 parse + JIT compile 成本。低配机每 10KB JS 解析约 0.5-1ms，这部分省 **~8-16ms 首屏时间**。

#### 2. AI 提示 marquee 从永久 rAF 改为可见性闸门

顶部那条 "图片生成后建议截图另存避免 AI 指纹" 横向滚动文案，之前用 `requestAnimationFrame` 永久循环驱动，每帧（16ms）跑 `getBoundingClientRect` + `style.transform = translateX(...)`。**banner 滚出视口 / 用户切到别的 tab / 浏览器后台都照吃 CPU**——低配机的一个常驻税。

新版加双闸门：
- **IntersectionObserver**：banner 进视口才启动 rAF，离开立刻 `cancelAnimationFrame`
- **`visibilitychange`**：页面切到后台（document.visibilityState='hidden'）立刻停 rAF，回前台再启

实际效果：用户看 sidepanel 第一屏时（banner 通常在顶部，可见）正常滚动；scroll 一下让 banner 出视口后，CPU 占用降到 0。

#### 3. 首屏错峰：封面快捷卡片 / 保活长连接 / 菜单刷新延后到 idle

之前 popup / sidepanel `init()` 同步排入：
- `initPinnedCover()`：4 个 `chrome.storage.local.get` + 1 个 `fetch(prompts/coverPrompts.json)` + render + 一坨 `attachListeners()`
- `setupAlivePort()`：`chrome.runtime.connect()` 唤醒 SW 建立长连接

这些和首屏菜单 / 关键字徽章渲染抢主线程，但用户感知不到它们（pin 卡片默认 `hidden=true`，alive port 是后台状态）。改成 `requestIdleCallback(fn, { timeout: 1200/1500 })` 推迟到浏览器空闲后再跑。

#### 4. 首屏关键字取数错峰，不撞 SW 冷启动

商店生产环境 SW 30s idle 即被回收，popup / sidepanel 一打开就发 `sendMessage('getKeyword')` 会触发 SW 冷启动（importScripts 17 个 legacy + side effects ~500ms-2s），跟首屏渲染抢 CPU。

v1.6.22 双管齐下：
- **popup**：`requestIdleCallback` timeout 从固定 300ms 调成"有缓存 500ms / 没缓存 1200ms"，重试次数从 `retries: cached ? 0 : 1` 全部归零（避免一次失败叠加 5000ms 二次等待）
- **sidepanel**：首屏 cache miss 时不再立刻发 sendMessage，而是 `scheduleRefresh({ delayMs: 700 })` 推迟 700ms

### 🐛 修复

#### 1. 新开网页时菜单卡顿 / "后台启动较慢，请重试"

低配 Windows 上每次新开网页，`chrome.tabs.onUpdated` 在**单次跳转里会触发 3 次**（title / loading / complete）。原 SW 逻辑每次都跑：
- `prefetchMenuState` + `refreshMenuTitle`（含 `chrome.scripting.executeScript` 探测）
- complete 阶段额外 `syncSelectionFromTab`（content.js 尚未注入会触发 reinject + 重试 sendMessage）
- 还有一个 `setTimeout(300ms)` 延迟二次 prefetch

SW 持续忙 3-6 秒，期间 popup / sidepanel 发出的 `executeMenuAction` 排队，`runtimeClient.js` 5000ms timeout × 2 retry 仍可能撞上忙窗口超时，触发 popup.js 的"后台启动较慢"toast。

v1.6.22 新增 `BG_TABS_ONUPDATED_LITE = true` 模式（默认开）：
- title 变化只刷 in-memory cache（更新 tab 标题用），跳过 prefetch / refreshMenuTitle
- loading 只清空选区 / fallback 缓存，跳过 prefetch
- complete 只跑一次 prefetch + refreshMenuTitle，**跳过 syncSelectionFromTab**——content.js 在 `manifest.run_at: document_start` 已自动注入，它读到 selection 后会主动 `sendMessage('selectionChanged')` 上来，SW 不需要主动 fetch + reinject
- 删除 setTimeout 300ms 二次 prefetch（SPA 站点菜单标题最坏延迟一次轮询，可接受）

回滚预案：若上架真机后右键菜单标题 / 关键字同步出问题，把 `background/events.js` 顶部那行 `const BG_TABS_ONUPDATED_LITE = true;` 改为 `false`，发 v1.6.23 patch 即可恢复 v1.6.21 完整行为，**完整老代码一行未删**。

#### 2. 菜单标题被动刷新不再发额外探测

`KeywordService.computeSearchTextForTab` 新增 `allowFallbackSelectionFetch` 选项（默认 `true` 不变）。被动路径（`KeywordService.compute` / `refreshMenuTitle` / `onShown` 监听）传 `false`，选区为空时不再多发一次 `chrome.scripting.executeScript` 探测。显式刷新（`forceFetchSelection`）仍走原路径不受影响。

### 🛠 技术改动

- 新增 `sidepanel/voice.js`（502 行）—— IIFE 包裹注册 `globalThis.CCSSidepanelVoice = { VoicePanel, OffscreenSpeechRecognizer, VoiceRecognitionError }`，HTML 不 eager 引用，由 `SidePanelRenderer._ensureVoiceLoaded()` 通过 `document.head.appendChild(<script>)` 动态注入，Promise 缓存供并发点击复用。
- `sidepanel/sidepanel.js` 加 `performance.mark('ccs-sidepanel-start' / 'ccs-sidepanel-rendered')` + `measure('ccs-sidepanel-ttfb')` + `console.log('[触触搜][PERF] sidepanel TTFB: Xms')`，与 popup 同款打点。开发者 / 高级用户可在 DevTools console 看真实 TTFB 数字。
- `popup/popup.js` 删除 dead code `_preloadEnableState`（写 `this._cachedEnabled` 但全文件无任何读它的地方）。
- 显式声明 `sharp` 为 dependency（Plasmo 构建链 native module）。Plasmo 间接依赖 sharp 做图片处理，darwin-arm64 binary 在某些 npm 版本会被 optional dep 算法跳过导致 build 挂；显式声明 + `npm install --include=optional` 确保 platform binary 进 lock。
- 远端 + 本轮新代码均通过 `npm test`（eslint + typecheck + 7 个 verify-* + plasmo:build + perf-budget + sw-bridge）。Plasmo bundle 预算保持：popup 191.8KB / sidepanel 174.8KB / SW 78.3KB / content 94.9KB 均未变（这些是 Plasmo 编译 src/* 的 bundle，不是生产 popup/sidepanel 用的，仅作 SW + 未来 port 储备）。

## 兼容性

- Chrome 114+（不变）
- Manifest V3
- 用户已有数据全部兼容（storage key 没改一个）
- 语音功能用户：升级后行为无差异——开关默认状态、引擎别名、状态机全部 1:1 保留，只是加载时机变了

## 已知限制

- `BG_TABS_ONUPDATED_LITE = true` 模式下，**SPA 单页应用**（如 X.com、YouTube 子页跳转）的右键菜单标题在 SPA 内部路由切换时**最坏延迟一次轮询**才更新——原逻辑通过 `setTimeout(300ms)` 二次 prefetch 兜底，新版去掉以省 SW 忙时。如果有用户反馈 SPA 菜单标题滞后，可通过设置 `BG_TABS_ONUPDATED_LITE = false` 回滚。
- 语音模块 lazy load 首次点 🎤 比之前多一次脚本下载 + 解析（~20-30ms），用户感受是"点 🎤 后微微等一下出 panel"，比之前快速出 panel 慢 1-2 帧，但比首屏每次都付这 ~16ms parse 成本划算很多。

## 升级提示

从 v1.6.21 升级：商店推送后浏览器自动更新即可。

主观感受变化（按显著性排序）：
1. **打开侧边栏快了**：低配 Windows 上"卡 1-2 秒才看见菜单"应消失
2. **新开网页右键菜单更顺**：之前点扩展图标偶尔提示"后台启动较慢，请重试"应大幅减少
3. **CPU 占用更低**：sidepanel 开着不操作时不再有常驻 rAF tax，电池 / 散热可感
4. **首次点 🎤**：比之前慢一点点（额外 ~20ms 加载脚本），从此之后正常

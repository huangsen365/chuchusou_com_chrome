# 触触搜 v1.6.18 发布说明

发布日期：2026-05-17

## 一句话总览

**首个真正基于 Plasmo 框架发布的版本** —— `./build.sh` 从 v1.6.0 时代的「直接 rsync 源目录」模式正式切到走 `npm run plasmo:build` 出 build/chrome-mv3-prod/ 再打 zip。同时修一个 YouTube 关键字识别 bug。**用户感知行为只有 YouTube 修复一处可见**，其它 manifest 入口（SW / popup / sidepanel / content_scripts）仍指向 legacy 文件，行为与 v1.6.17 完全一致。

## 主要更新

### 🐛 修复

#### YouTube 关键字误取 video ID

**症状**：在 `https://www.youtube.com/watch?v=IurBXe0jpVg` 这种页面唤起触触搜菜单时，关键字栏会显示 11 字符 video ID（`IurBXe0jpVg`）而不是视频标题。

**根因**：`background/keywords.js` 的 `extractSearchKeywords` 没有 YouTube 硬编码分支，落到启发式兜底 `heuristicExtractFromParams`。`v` 不在 `COMMON_QUERY_KEYS` 常用关键字白名单里，但 11 字符 base64 ID 通过了长度（+1.1 分）和"不是 hex hash"过滤，启发式以 1.1 分 > 0 命中，返回了 video ID。启发式抢跑后，行 270 的 `tab.title` fallback 永远到不了。

**修法**：加 `HOSTS_SKIP_HEURISTIC = ['youtube.com', 'youtu.be']`。命中后跳过启发式，直接走 title fallback —— 此时 `tab.title` 已经是 `"Awesome Video Title - YouTube"`，suffix split `' - '` 自动剥掉 ` - YouTube`，得到正确的视频标题。

**HOSTS_SKIP_HEURISTIC 这个名单可扩展**：未来遇到 spotify track id / twitter status id 等同类站，往那个常量数组加一行即可。

scripts/verify-background-extras-dual.mjs 加了 2 个 YouTube dual-run 用例（`www.youtube.com/watch?v=...` 和 `youtu.be/...` 短链都覆盖），未来 legacy 或 TS port 任一边漏改都会被 npm test 拦下来。

### 🛠 技术改动

#### 1. build.sh 切到 Plasmo（核心结构性改动）

**v1.6.18 之前**：`./build.sh` 直接从源目录 rsync 文件到临时目录再 zip。完全绕过 Plasmo —— `npm run plasmo:build` 产生的 Plasmo bundle 根本不会进 zip。这种「Plasmo 跑测试 vs build.sh 跑发布」的双轨制是 v1.6.0 引入 Plasmo 时的过渡形态。

**v1.6.18 起**：`./build.sh` 是 Plasmo 的 thin wrapper：

1. 调 `npm run plasmo:build`（= Plasmo 编译 src/* → bundles + compat postbuild 把 legacy 文件复制进 build/ + 把 manifest 入口按 legacy/Plasmo 选项 patched 好 + verify-plasmo-compat-build 检查 33 个 manifest-ref 文件齐全 + JS 语法合法）
2. 把 build/chrome-mv3-prod/manifest.json 的 version 字段写为目标版本
3. 把整个 build/chrome-mv3-prod/ 打成 zip 到 `../chuchusou_chrome_extension_vX.Y.Z.zip`

**zip 大小变化**：v1.6.17 是 ~210K / ~92 文件；v1.6.18 是 ~462K / ~132 文件。多出的 250K / 40 个文件全部是 Plasmo bundle（根 `popup.html` / `sidepanel.html` / `content.{hash}.js` / `static/background/index.js` / `popup.{hash}.{js,css}` / `sidepanel.{hash}.{js,css}` 等），目前**不被 manifest 引用**所以不被 Chrome 加载，但它们是「v1.6.18 = 真正基于 Plasmo 发布」的物证。下个 minor 版本计划把 manifest 入口切到 Plasmo bundle，到时这些文件就会真正运行起来。

#### 2. background SW 模块 TypeScript 化（第 5 批）

把 5 个 legacy SW 模块 port 到 TS，**与 legacy 并存不替换生产路径**：

| Legacy 路径 | TS 路径 | 行数变化 | 备注 |
|---|---|---|---|
| `background/voiceOffscreenBridge.js` (100) | `src/background/voiceOffscreenBridge.ts` (189) | +89 | 类型化 + deps 注入开销 |
| `background/KeywordService.js` (220) | `src/background/KeywordService.ts` (225) | +5 | 类型化几乎平 |
| `background/config.js` (312) | `src/background/config.ts` (254) | **-58 (-19%)** | 4 个 `loadXxxConfig()` 收敛到一个 generic helper，4 个 `buildXxxPrompt()` 收敛到 `_fillTemplate()` |
| `background/init.js` (448) | `src/background/init.ts` (206) | **-242 (-54%)** | 删 `useNewSystem=true` dead branch；prewarm 复用 initPrewarming.ts；调试 globals 改为按需挂载 |
| `background/KeywordSyncManager.js` (501) | `src/background/KeywordSyncManager.ts` (246) | **-255 (-51%)** | 删 `_setupOnShownListener` 整段 80 行 dead code（legacy 第一行就 `onShownSyncEnabled=false` 早 return）；删 compat 期间占位 noop `updateFallback` / `updatePageTitle`；提取 `extractKeyword(tabId)` private helper 消除三路读取逻辑重复 |

**累计统计**：本 release 5 个 ports 共 1581 legacy 行 → ~1120 TS 行（**减 29%**），同时新增 5 段 dual-run / structural verifier 锁住等价性。

到 v1.6.18，src/background/ 已 port 14 个文件，剩 5 个 legacy 未 port：
- `events.js` (1512, 51 chrome.*)
- `menuBuilder.js` (990, 15 chrome.*)
- `base.js` (890, 30 chrome.*)
- `menuHandlers.js` (611, 42 chrome.*)
- `index.js` (57, 已由 src/background.ts 替代)

#### 3. 新增 verify:sw-bridge 测试关（npm test 第 12 道关）

`scripts/verify-sw-bridge.mjs` 锁住 3 件事：

1. `src/background.ts` 的 importScripts 列表（24 个 legacy 模块绝对 URL）顺序敏感地等同于 legacy `background/index.js` 的 ACTIVE importScripts（跳过 commented-out 行）
2. build/ 里 24 个 target legacy 文件全部存在
3. Plasmo 编译出的 SW bundle 真的包含 `self.importScripts(...)` + 关键 target 引用

未来如果 src/ 或 legacy 任一边漏改 SW 模块清单，CI 立刻失败。

#### 4. dual-run verifier 大扩展

`scripts/verify-background-extras-dual.mjs` 现在覆盖 8 个模块：StateManager + keywords + promptBuilders + voiceOffscreenBridge + KeywordService + config + init + KeywordSyncManager。其中 config 的 buildXxxPrompt 4 个函数 + isMenuEnabled + getEngineTitle 都是与 legacy 真实 dual-run（同输入跑两边比 output）。

## 兼容性

- Chrome 114+（与 v1.6.17 一致）
- 用户安装路径无变化
- 所有 chrome.storage.local 键无变化
- 用户配置（黑名单 / 调试 / 语音开关 / 自定义提示词等）全部保留

## 已知限制

- **manifest 入口仍全部 legacy**：service_worker / default_popup / side_panel.default_path / content_scripts 都指向 legacy 文件，与 v1.6.16 / v1.6.17 完全一致。Plasmo bundle 在 zip 里但不被 Chrome 加载。下个 minor 版本计划切。
- **5 个 legacy SW 文件未 port**：events.js / menuBuilder.js / base.js / menuHandlers.js / index.js，共 ~4000 行。这些是 SW 的事件循环 + 菜单构建核心，紧密耦合，需要分批 port 或整组 dual-run 验证。

## 升级提示

老用户从 v1.6.17 升到 v1.6.18 会感知到的变化：

- **YouTube 页面菜单关键字现在正确显示标题**而不是 11 字符 ID 乱码
- 其它任何交互（右键菜单 / popup / sidepanel / 内容选区追踪 / 黑名单 / 快捷键等）**完全没变化**

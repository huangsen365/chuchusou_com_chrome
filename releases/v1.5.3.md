# 触触搜 v1.5.3 发布说明

发布日期：2026-05-01

## 一句话总览

侧边栏 UX 持续打磨——封面卡片置顶 + header 收窄省空间，剪贴板 / 自定义风格多项体验修复，新增 ⓘ 详情弹层。

## 主要更新

### ✨ 新功能

#### 1. 封面卡片置顶 + header 收窄

- `.sp-pin`（封面生成器卡片）从主滚动区搬进 `.sp-sticky-top`，菜单滚动时常驻视野
- 最终 sticky 顺序：

  ```
  ┌─────────────────────────┐
  │ 触触搜 (header, 收窄了) │  ← 蓝色压扁 ~22px
  │ ⚠️ AI 检测温馨提示 ──── │  ← 滚动那句
  │ 📋 从剪贴板读取关键字   │  ← 兜底入口（hidden 时不占位）
  │ 🎨 封面生成器 [✏️]      │  ← 永远在视野
  └─────────────────────────┘
  （菜单从这往下滚）
  ```

- header 收窄数据对照：

  | 属性 | 之前 | 现在 |
  |---|---|---|
  | header padding | 14px 16px | 6px 14px |
  | 🔍 icon | 20px | 15px |
  | 标题 "触触搜" | 16px | 13px |
  | keyword 徽章 | 12px / padding 3 10 | 11px / padding 2 8 |

#### 2. 封面卡片 ⓘ 详情弹层

封面卡片标题旁新增 ⓘ 图标，**点击**（非 hover）展开详情卡片，触屏 / 桌面行为统一。4 种关闭路径：再点 ⓘ / 点 × / 点弹层外部 / ESC。

弹层内含 4 个分区：

| 分区 | 内容要点 |
|---|---|
| 📝 文字篇幅 | 主文案推荐 **10–30 字**（标题 + 副标题）、过短/过长/带换行的视觉影响 |
| 🎨 风格 / 📐 比例 | 引导用户去 ✏️ picker 切换内置风格 / 自定义预设 / 画面比例 |
| 💡 不会写自定义风格？ | 指引到 picker 内的「💡 不知道填什么？」按钮（跳 ChatGPT 列 30 个参考） |
| 📋 文字来源 | 选中文本优先；不支持选区页面用顶部「📋 从剪贴板读取关键字」兜底 |

技术细节：`<span role="button" tabindex="0">` 嵌在 `<button>` 内避免 nested button 非法 HTML；click 靠 `stopPropagation` 阻止冒泡到外层 action；`aria-expanded` 同步状态；键盘 Tab focus + Enter/Space 切换。

#### 3. 自定义风格 picker 加「💡 不知道填什么？」帮助按钮

部分用户反馈"想不出风格关键词怎么办"。picker 自定义预设 label 旁加帮助按钮，点击跳 ChatGPT 让它直接生成 30 个封面风格参考列表（plain text 一行一个，便于复制回来选用）。

#### 4. 置顶卡片标题加字数提示

`封面生成器` → `封面生成器（建议字数适中）`，配合 `title` 属性 hover 兜全文：「建议选择字数适中，否则图片效果不佳」。配合 ⓘ 弹层的"文字篇幅"分区形成"短提示 + 详细说明"两层结构。

### 🐛 修复

#### 剪贴板读取被 500 字符 cap 截断

**用户反馈**：复制多段换行长文后点 📋，发现内容没完全捕获。

**根因**：sidepanel 剪贴板按钮硬截 500 字，超出部分被吃掉。这个 cap 是历史防御性遗留，但 backend `TEXT_LIMITS_ENABLED` 已关闭、引擎级保护交给 `applyTextLimit` 按 menuId 处理，前端没必要再硬截。

**修复**：上限 500 → 6000 对齐 backend `LIMITS.aiChat`。下游字数保护逻辑不变。

#### 剪贴板多段内容灌给搜索引擎查询失败

**用户反馈**：剪贴板捕获 OK，但用 Google / 百度 / Chrome 搜索时"串联不起来"——查询返回不相关结果。

**根因**：之前所有菜单类型都用 `keyword.raw`（保留 `\n`），编码后变成 `%0A` 灌进搜索 URL。AI 对话端能正确还原段落，但搜索引擎把 `%0A` 当查询噪声，语义被破坏。

**修复**：`handleClick` 按 `item.type` 分流——

| 目标类型 | 取值 | 原因 |
|---|---|---|
| `search` / `ai-search` / `ecommerce` / `translate` / `portal` | `keyword.text`（合并空白） | 单行查询，避免 `%0A` 噪声 |
| `ai-chat` / `fastqa` / `top100` / `optimize` / `cover` / `tool` / `transform` | `keyword.raw`（保段落） | 保留多段结构，AI 端能正确处理 |

#### 手动剪贴板 keyword 优先级被悄悄替换

**用户反馈**：用了一次 📋 后，第一次点菜单 OK；第二次点菜单时"系统回到默认机制"——剪贴板内容失效。

**根因**：之前 `refresh()` 的"保护手动 keyword"判定是 `keywordSetManually && (!newKeyword || !newKeyword.text)`——**只在自动提取为空时**才保留手动值。一旦后台对当前 tab 返回任意内容（标题提取 / 缓存选区），剪贴板内容就被覆盖。每次 `handleClick` 都会触发 `refresh()`，所以第二次点击时手动值已被冲掉。

**修复**：手动设过 keyword 是强烈意图信号——URL 不变就一律保留，唯一退出条件：URL 切换（用户主动换页）或用户再点 📋 写新值。

#### 自定义预设 textarea 保存残留脏数据

之前直接存 textarea 原文：行首尾空格、多余空行、连续空行都会写入 storage。

**修复**：保存路径统一走 `parseCustomLines + join('\n')`：每行 `trim()` + 丢空行 + 重新拼接。脏输入

```
  风格 1   

  风格 2
   
风格 3   
```

清洗后存的是

```
风格 1
风格 2
风格 3
```

### 🔧 改进

#### picker 自动滚顶

因为 `.sp-pin` 现在常驻顶部，picker 仍在主滚动区——用户滚到中段时点 ✏️，picker 出现在视野外（在头顶上方）。`openPicker()` 末尾加 `window.scrollTo({ top: 0, behavior: 'smooth' })` 确保 picker 总是可见。

#### 自定义预设 label 不再被强制换行

加了「💡 不知道填什么？」按钮后，原 CSS（`.sp-pin-custom-label` 上的 `flex: 1` + `min-width: 0`）允许 label 在容器空间不够时被强制中途断词，视觉很丑。改用 `white-space: nowrap` 锁住 label 整段、容器 `flex-wrap: wrap` 让按钮在空间不够时优雅落到下一行。label 永远完整。

### 🛠 技术改动

- 新增 storage key：（无）—— v1.5.3 没有新增持久化字段
- `sidepanel.js` 新增方法：`bindTaskInfoPopover()`（详情弹层 4 种关闭路径管理）
- `sidepanel.js` 修改方法：
  - `openPicker()`：末尾加自动滚顶
  - `savePicker()` 自定义分支：用 `parseCustomLines + join` 清洗保存
  - `refresh()`：弱保护升级为强保护
  - `handleClick(item)`：按 `item.type` 分流取 `keyword.raw` 或 `keyword.text`
  - `bindClipboardButton()` click handler：500 → 6000 字符 cap
  - `attachListeners()`：新增 `bindTaskInfoPopover()` 调用
- `sidepanel.css` 新增样式段：
  - `.sp-pin-task-row` / `.sp-pin-task-info` / `.sp-pin-task-popover` 系列（约 80 行）
  - `.sp-pin-custom-header` / `.sp-pin-custom-help` 帮助按钮（约 30 行）
  - `.sp-header` 收窄相关属性调整
- 新增常量 `COVER_STYLE_REFERENCE_URL`：picker 内「💡 不知道填什么？」按钮目标，跳 ChatGPT 让它列 30 个封面风格

## 兼容性

- Chrome 114+（Manifest V3 + chrome.sidePanel API）
- 与 v1.5.2 完全兼容，旧用户升级直接生效
- 无新增 storage key，老数据零迁移

## 已知限制

- ⓘ 详情弹层 `max-height: 70vh` —— 极矮窗口（如 < 500px 高）下内容仍可能内滚
- 自定义预设 textarea 容量上限沿用 v1.5.2 的 600 字符
- 剪贴板单次读取上限 6000 字符（与 AI Chat 引擎硬上限对齐）

## 升级提示

强烈建议老用户升级 —— 修复了 v1.5.2 三个用户感知较强的体验 bug：
1. 剪贴板长文被截到 500 字
2. 剪贴板内容传给搜索引擎查询失败
3. 第二次点菜单时剪贴板内容神秘失效

外加封面卡片置顶让常用入口不再被滚走，整体侧边栏体验提升明显。

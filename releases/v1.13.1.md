# 触触搜 v1.13.1 发布说明

发布日期：2026-09-17

## 一句话总览

**ChatGPT 长文页的「注入X草稿 / 生成封面」按钮不再一直灰着** —— 标题在块头部的新版 writing block 也能正确读到整篇文章；对外文案跟进 ChatGPT Images 2.5。

## 主要更新

### 🐛 修复

#### 「注入X草稿 / 生成封面」按钮出现了却一直点不了

症状：长文改写完成后，文章块右上角的两个按钮出现了，但一直是灰的，悬停提示「暂未读取到完整文章，当前操作不可用」，等多久都不变。

原因：ChatGPT 的 writing block 现在把**文章标题放在块头部**，编辑器里的正文直接从二级标题开始。触触搜此前只认编辑器里的一级标题，于是判定「没有标题」、整篇文章读取失败，按钮就一直处于不可用状态。冒烟夹具一直是按「一级标题在编辑器里」造的，所以自动化没抓到。

现在：编辑器里没有一级标题时，改从块头部取标题（剔除按钮和触触搜自己的动作条）。按钮正常变为可点，注入 X 草稿的标题和封面提示词里的标题都用头部那一条。有一级标题的旧结构行为不变。分享页（`chatgpt.com/share/…`）与普通对话页同样适用。

### 🔧 改进

- 对外文案「ChatGPT Images 2.0」→「ChatGPT Images 2.5」：扩展名称与描述、README、欢迎页、侧边栏帮助文案与「Google 搜提示词」按钮、封面引擎 label（`engines.json` / `coverPrompts.json` 双轨）。历史 CHANGELOG 与发布说明保持原样。

### 🛠 技术改动

- `modules/longArticleActions.js`：新增 `HEADER_SELECTOR`、`MAX_TITLE_LENGTH` 与 `headerTitleFrom(block)`；`extractArticleSnapshot` 无 `<h1>` 时回退。TS 口径 `src/content-modules/longArticleActions.ts` 只是薄包装，无需改动。
- 冒烟新增 header 标题回退链路（`unavailable` → `ready` → cover 任务入参以 header 标题开头），并修掉两个测试层面的坑：后台标签 `requestAnimationFrame` 不触发（先 `Target.activateTarget`），以及按钮点击后 3 秒 busy 保护期内 `.click()` 为空操作（先等恢复）。

## 兼容性

- Chrome 114+（不变）；Manifest V3；用户数据全部兼容
- **无新增权限**、无存储结构变化、无服务器依赖、无新增站点匹配
- **扩展显示名称变为「触触搜 - ChatGPT Images 2.5 封面生成器 / 多 AI 速答 / 提示词优化」**（仅文案，功能与入口不变）
- 未删除任何菜单项或入口

## 已知限制

- 沿用 v1.13.0 已知限制
- 头部标题回退依赖 ChatGPT 的 `data-testid="writing-block-header-surface"` / `writing-block-header-sticky-container` 结构；若 ChatGPT 再改版，可能退回「暂未读取到完整文章」状态（不会误注入，只是按钮不可用）
- 按钮点击后有 3 秒保护期显示「✓ 已完成」并禁用，属预期，不是失效

## 升级提示

- 从 v1.13.0 升级：之前在 ChatGPT 长文页遇到「按钮灰着点不了」的，升级后**刷新一下那个页面**即可（扩展升级不会自动刷新已开标签；X / 知乎页面有升级提示，ChatGPT 页面没有）
- 扩展名称里的「2.0」变成「2.5」，其它一切照旧
- 其余功能与 v1.13.0 一致
- **上架说明**：本版为修复 + 文案，不新增商店描述，沿用 [releases/v1.13.0.md](./v1.13.0.md) 的「商店描述」段（把其中的「2.0」按需改成「2.5」）。**扩展名称随 manifest 变化**，上传后商店列表名称会一并更新。若商店线上版本仍停留在 v1.8.0（v1.9.0 起均未上传），请把 [releases/v1.9.0.md](./v1.9.0.md)、[releases/v1.11.0.md](./v1.11.0.md)、[releases/v1.12.0.md](./v1.12.0.md)、v1.13.0 的商店描述合并后再发布。

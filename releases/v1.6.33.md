# 触触搜 v1.6.33 发布说明

发布日期：2026-06-13

## 一句话总览

**AI 提示词填充可靠性大修 + 页面加载中也能取关键字** —— 修掉文心/Claude"填充后点发送没反应、字符驻留、气泡挡按钮"的全部三个根因，侧边栏/popup 不再死等页面加载完才显示关键字。

## 主要更新

### 🐛 修复

#### 1. 填充后点发送"没反应/字符驻留"（文心一言为主，其它平台同理）

**症状**：长提示词自动填充成功后点击发送，有时毫无反应、字符留在输入框；或发送后字符又出现。

三个根因全部修掉：

- **提示气泡吞点击**：填充完成的提示气泡固定在右下角、层级最高且不可点透——恰好罩住各家 AI 都放在右下角的发送按钮，气泡存在的 3 秒内点发送等于点在气泡上。现改为**页面顶部**显示且**可点透**（这同时就是 Claude 用户看到的"填充内容挡住发送按钮"）。
- **旧提示词被写回**：双通道投递的"巩固重填"会在你发送后把旧提示词重新填回输入框。现在加了"双向包含"守卫：只修复提示词自身的损坏形态（被编辑器截断/翻倍），**你发送后输入框被清空、或已开始打新草稿时绝不触碰**。
- **文心 Slate 编辑器状态脱钩（根治）**：文心的输入框基于 Slate.js，内部模型与页面隔离世界不互通——填充后"看得见字"，但站点发送时读内部模型拿到空。现通过 `chrome.scripting`（MAIN world）直接同步 Slate 编辑器状态；并配**发送驻留侦测器**：万一发送后内容原地不动，自动再同步一次输入状态、提示"请再点一次发送"，并把诊断（含填充通道）写入日志，下次复现可一锤定音。

#### 2. 页面加载中侧边栏/popup 取不到关键字

**症状**：页面大部分内容已渲染、标题已出、甚至已能手动选中文字，但侧边栏仍提示"没有选中关键词"或显示空白。

根因全在打开头几秒的快速通道（boot 层）：

- 关键字请求预算只有 1500/1600ms 单次零重试——页面加载期打开恰逢后台冷启动是常态，稳定超时（v1.6.32 给主程序修过，boot 层漏了，现已对齐：3000ms + 重试）
- 侧栏启动只读缓存、不主动取——现在**启动即取**，且页面标题/URL 一到就刷新，**不等页面加载完**
- 点菜单用旧缓存、不感知你刚选中的文字——现在**点击瞬间重新探测页面选区**，优先用你当前选中的内容

#### 3. 长提示词从 popup/侧栏点 AI 对话被 URL 截断

快速通道此前直拼 URL 打开 AI 对话页；长内容会撞 URL 长度上限。现统一走后台中继 + 自动填充，与右键菜单行为一致。

- **真 Chrome 自动化回归体系**（本版最大的内部投资）：headless Chrome 真实装载构建产物，19 条端到端断言（SW 启动/桥接/11 个消息协议/端口生命周期/真实选区捕获/右键菜单动态标题/popup+侧栏启动与点按）+ 6 场景 AI 填充 UX 套件 + Slate 注入安全契约（非文心来源必拒）。全部进 `npm test` 与 CI，并且完全不依赖外网（搜索引擎域名映射到本地夹具）。
- 退役 6 个已脱离运行时的 legacy 后台文件（~3200 行）：不再随商店包发布，包体瘦身；防回归守卫 + OneDrive 同步冲突副本拦截。

- 文档（CLAUDE.md / README / 技术债审计）与代码现状全面对齐；README 不再宣称已暂时关闭的"悬浮浮窗"功能。
